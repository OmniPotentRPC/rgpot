.. index:: pair: function; forceBatch
.. _doxid-classrgpot_1_1_potential_base_1a8087be94eea866e7ad37a54a229c184a:

.. ref-code-block:: cpp
	:class: doxyrest-title-code-block

	virtual void forceBatch(const :ref:`ForceBatch<doxid-structrgpot_1_1_force_batch>`&)

Evaluate a batch of independent systems in one call.

Callers running multi-system methods (NEB images, dimer endpoints) use this instead of a loop over ``operator()``, so a kernel that can evaluate many systems at once a GPU model batching into a single forward pass, say gets the chance to.

Every kernel supports this call. ``:ref:`caps() <doxid-classrgpot_1_1_potential_base_1a32efde0927ea88bf90e3d24fbb948899>```.batched reports whether it is served natively or by the default per-system loop, which callers read when deciding whether batching is worth the marshalling.

Results land in ``batch.out``; see :ref:`ForceBatch <doxid-structrgpot_1_1_force_batch>` for the buffer contract.

.. ref-code-block:: cpp

	virtual uint64_t paramsKey() const

Fingerprint of the potential's parameter set.

Mixed into the result-cache key so results never cross parameter sets. Implementations hash their config field by field (see :ref:`ParamHash.hpp <doxid-_param_hash_8hpp_source>`) plus a kernel-version salt that changes whenever the numerics change. The default (0) suits parameter-free potentials whose numerics never changed.
