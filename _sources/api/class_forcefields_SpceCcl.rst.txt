Detailed Documentation
~~~~~~~~~~~~~~~~~~~~~~

SPC/E+CCl water potential. This potential combines potential SPC/E (for intermolecular interactions) with potential CCL (for intramolecular interactions). The functions and parameters for the SPC/E are from :ref:`Berendsen, et al. <doxid-classforcefields_1_1_spce_ccl_1berendsen1987>`. References for potential CCL can be found in in class :ref:`Ccl <doxid-classforcefields_1_1_ccl>` 's documentation. The rules used to merge these two potentials were taken from :ref:`Amira, et al <doxid-classforcefields_1_1_spce_ccl_1amira2004>`.

	void computeHH_O_(const int nAtoms, const double R[], double F[], double& U, const double b[])

Compute the forces and the energy. The order of the atoms is very important. For this function the order is H1, H1, H2, H2, etc ... , O1, O2, etc ... The numbers are for the molecules. The suffix HH_O\_ is to reminds the ordering of the atoms. It indicates the position of the atoms of the first molecule, while the underscore marks the locations of other atoms.

.. warning::

	Be careful with the order of the atoms.

.. ref-code-block:: cpp

	void computeHH_O_(const int nAtoms, const double R[], double F[], double& U, const double b[], const bool fixed[])

Compute the forces and the energy (with fixed atom optimisation). In a simulation, some atoms may be fixed (not allowed to move). Computing the interaction between two fixed atoms is useless. When the potential knows which atoms are fixed, it can avoid these useless computations.



.. rubric:: Parameters:

.. list-table::
	:widths: 20 80

	*
		- nAtoms

		- Number of :ref:`Atoms <doxid-class_atoms>`.

	*
		- R

		- coordinates.

	*
		- F

		- Forces.

	*
		- U

		- Potential energy.

	*
		- b

		- Periodic boundaries.

	*
		- fixed

		- The length of the array must be equal to *nAtoms* in compute(). True when atom is fixed, false otherwise.
