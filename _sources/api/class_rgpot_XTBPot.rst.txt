Detailed Documentation
~~~~~~~~~~~~~~~~~~~~~~

Linked GFN-xTB pot (NEEDED libxtb).

libxtb exposes a stable **ISO_C_BINDING** C API (``xtb.h``): opaque ``xtb_TEnvironment`` / ``xtb_TCalculator`` / ``xtb_TMolecule`` / ``xtb_TResults`` handles with explicit create/update/destroy. We test and use that C contract—not free-form Fortran ABI. Each ``:ref:`XTBPot <doxid-classrgpot_1_1_x_t_b_pot>``` owns its handles. The first force builds the molecule. Later forces call ``xtb_updateMolecule`` and keep the SCC wavefunction in the results object while no atom moves by more than ``:ref:`XTBConfig::warm_move <doxid-structrgpot_1_1_x_t_b_config_1a77d9b5f2284813a43156e3ce6fcecf5c>``` (1 Angstrom unless changed). A larger move, a new composition, or ``:ref:`reset() <doxid-classrgpot_1_1_x_t_b_pot_1adb24312e22eb779feb00192475c56ba4>``` drops that object so the next single point uses xtb's own guess. ``xtb_releaseOutput`` is called on create (library recommendation for multi-env processes). Do not share one instance across threads; distinct instances may be used from different threads if the loaded libxtb build is reentrant for independent handle sets.

For hosts that must not NEEDED libxtb, use ``:ref:`XTBDlopen <doxid-classrgpot_1_1_x_t_b_dlopen>``` + ``libxtb_engine.so`` instead (always built; no ``-Dwith_xtb`` required).
