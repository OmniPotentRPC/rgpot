Detailed Documentation
~~~~~~~~~~~~~~~~~~~~~~

Full neighbour tables in CSR form, built with rgpot's neighbour query.

Every ported potential evaluates forces as a *gather* : atom ``i`` sums the whole force acting on it from its own neighbours, and writes only ``f(:, i)``. Iterations of the atom loop then touch disjoint memory, so they run under ``do concurrent``. That needs a **full** list (both ``i->j`` and ``j->i``), with the pair vectors and distances already folded, so the kernels never redo minimum image arithmetic.

The search is ``:ref:`rgpot_nlist_fortran_build <doxid-interfacergpot__neighbors_1_1rgpot__nlist__fortran__build>```. A positive skin keeps the candidate list in an ``:ref:`rgpot_nlist_builder <doxid-structrgpot__nlist__builder>``` and reuses it while every atom has moved by at most half the skin. Each call still writes vectors for the positions it was given and keeps only pairs strictly inside the cutoff, which is the Verlet filter.

Cell convention: C callers hand over nine doubles, row-major, one cell vector per row. Fortran reads that same memory column-major, so a ``real(wp) :: cell(3, 3)`` dummy sees one cell vector per *column*. ``vec(3, npairs)`` is that same layout: column ``p`` is ``r_j - r_i``.
