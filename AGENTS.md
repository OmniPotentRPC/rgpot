# AGENTS.md

Instructions for anyone who changes rgpot.
The long form lives in the documentation under `docs/orgmode/`; this file is the
short path to the commands and rules that decide whether a change is accepted.

## What rgpot is

A C++ potential energy library with a Cap'n Proto RPC server (`potserv`), a C
ABI (the Rust crate `rgpot-core`), Python bindings, and adapters for LAMMPS,
GROMACS, OpenMM, PLUMED and i-PI.
Energies are eV, lengths Angstrom, forces eV/Angstrom, unless a page says
otherwise.

## Layout

| Path | What lives there |
|------|------------------|
| `CppCore/rgpot/` | The C++ library `librgpot`: one directory per potential family, the `Potential` base classes, the neighbour layers, the engine and plugin ABIs |
| `CppCore/rgpot/rpc/` | The Cap'n Proto schema, `potserv` (`server.cpp`), the local schema diffs under `local/` |
| `CppCore/rgpot/fortran/` | Fortran 2018 ports of legacy kernels (silicon, EAM, water) |
| `CppCore/tests/` | The C++ tests; `registry.txt` is the one test list for Meson and CMake |
| `rgpot-core/` | The Rust crate with the C ABI; `include/rgpot.h` is generated by cbindgen |
| `rgpot-pair/` | The Rust crate of inlinable pair kernels |
| `potctl/` | The project control plane (release lockstep, CI steps) |
| `engines/` | Engine plugins, host adapters, `rgpot-eval`, `rgpot-lj`, `rgpot-ipi-driver` |
| `python/`, `bind/` | The nanobind package `rgpot` and the binding policy header |
| `docs/orgmode/` | Documentation sources (org); `docs/source/` is the Sphinx project |
| `docs/` | `doccheck.py`, `inventory.py`, `gen_capnp_reference.py`, design notes (`*.md`), `newsfragments/` |
| `scripts/` | ABI baselines, `gen_llms.py`, `verify_dois.py`, helper scripts |
| `ci/gha/` | Nickel sources of the generated workflows |
| `third_party/`, `subprojects/` | Vendored code and Meson wraps |

Do not edit these by hand: `.github/workflows/*.yml` except
`ci-orchestrator.yml` (edit `ci/gha/*.ncl`, then run `pixi r -e cigen gen-gha`),
`rgpot-core/include/rgpot.h` (run `pixi r gen-header`),
`docs/orgmode/reference/capnp_schema.org` (run `python docs/gen_capnp_reference.py`),
`llms.txt` and `llms-full.txt` (run `python scripts/gen_llms.py`), and the
copies of the version listed in `ci/version/files.txt` (see "Versions").

## Environment

Everything runs through [pixi](https://pixi.sh).
The default environment has the compilers, Meson, CMake, Rust and the test
tools; other environments are named in `pixi.toml` (`docs`, `rpctest`,
`cigen`, `metatomicbld`, ...).

```bash
pixi install
pixi shell
```

## Build

Meson is the primary build system.
`docs/orgmode/reference/build_options.org` lists every option and default.

```bash
meson setup bbdir -Dwith_tests=true -Dwith_rpc=true --buildtype=debug
meson compile -C bbdir
```

CMake registers the same tests (`CppCore/tests/registry.txt`):

```bash
cmake -B build-cmake -DRGPOT_BUILD_TESTS=ON -DRGPOT_WITH_RPC=ON -DRGPOT_WITH_CACHE=OFF
cmake --build build-cmake
```

`bbdir` is the directory `potctl ci meson-test` uses by default.

## Test

```bash
meson test -C bbdir --print-errorlogs      # C++, Fortran and Python tests
ctest --test-dir build-cmake --output-on-failure
pixi r rust-test                           # Rust crates
pixi r potctl-test                         # potctl unit tests
python -m unittest discover -s tests/docs -p 'test_docs_*.py'
```

`potctl ci meson-test --rpc true --cache false` runs the CI leg for the Meson
build; `potctl ci --help` lists the others.
A test that needs software the machine lacks (an engine, a quantum code)
skips with the reason.

## Documentation

Pages are org files under `docs/orgmode/`.
Write prose as semantic line breaks, at most 80 columns, one sentence or clause
per line (`pixi r snapper-fix` applies the project's formatter).
Do not use em or en dashes as punctuation, exclamation marks, git hashes,
pull request numbers or ticket ids in a page.

Every code block carries `#+attr_rgpot: <kind>` above it (`run`, `compile`,
`syntax`, `fragment`, `signature`, `output`, `skip`; `output` and `skip` need a
reason).
`run` and `compile` blocks are executed against a build.

Checks (all must pass):

```bash
pixi r -e docs doccheck                          # reference, facts, blocks, coverage, inventory, generated files
pixi r -e docs doccheck --build-dir bbdir        # also runs the examples against a build
pixi r -e docs python -m unittest discover -s tests/docs -p 'test_docs_*.py'
pixi r -e docs doc-inventory                     # coverage table and the gaps
```

`doccheck inventory` fails when a public potential, C, C++ or Python name,
Cap'n Proto field, Rust item, program or `potctl` command has no documentation.
A potential needs a section headed `=Name=` in `docs/orgmode/howto/potentials-*.org`.
`doccheck generated` fails when `llms.txt`, `llms-full.txt`, the Cap'n Proto
page or `docs/dois.json` is stale.

Build the site exactly as CI does; a warning fails the build:

```bash
pixi r -e docs docbld     # mkrst, doxybuild, then sphinx-build -W --keep-going
```

Citations: every DOI a page cites is recorded in `docs/dois.json`.
`python scripts/verify_dois.py --update` resolves the new ones (it needs the
network) and `pixi r -e docs verify-dois` resolves all of them again.
Never cite a DOI that does not resolve.
Parameter values in a page are copied from the source or from the cited table.

## ABI and soversion rules

`docs/orgmode/contributing/developer/abi-bump.org` has the steps.
In short:

- The C++ soversion is `kCxxSoversion` in `CppCore/rgpot/abi/CxxLayout.hpp`.
  A change to the size, alignment or a field offset of a covered type moves the
  layout hash; bump `kCxxSoversion` in the same change and append a line to
  `CppCore/rgpot/abi/cxx_soversion_ledger.txt` (never edit a shipped line).
- `kCxxLayoutRevision` goes up when a change keeps every size and offset but
  alters the ABI (virtual function order, a field's meaning, a base class), and
  `kCxxSoversion` goes up with it.
- Changing the virtual functions of `Potential.hpp` also changes
  `kPotentialBaseVirtuals`, `kPotentialBaseCacheVirtuals` or
  `kPotentialVirtuals`.
- Copy a platform hash into `kCxxSoversionTable` only from CI for that
  platform, never from a local build.
- The C ABI stamp is `RGPOT_ABI_VERSION_MAJOR`, `RGPOT_ABI_VERSION_MINOR` and
  `RGPOT_ABI_LAYOUT_REVISION` in `rgpot-core/src/version.rs`: major for a
  change an old caller cannot survive, minor for an addition, layout revision
  for a struct change.
  Regenerate the header, and append each new exported function to
  `scripts/abi_core_baseline.txt` (the list only grows).
- `CppCore/rgpot/rpc/Potentials.capnp` and `rgpot-core/schema/Potentials.capnp`
  are the pinned upstream file byte for byte.
  Local additions are diffs under `CppCore/rgpot/rpc/local/`, and
  `Potentials.ordinals` is append only.

## Versions

One release version lives in `[workspace.package]` of the root `Cargo.toml`.
`potctl release sync VERSION` writes it, `pixi r -e version release-cog`
regenerates the other copies, and `potctl release assert` checks them.
Do not edit a version string in `meson.build`, `CMakeLists.txt`,
`pyproject.toml`, `towncrier.toml` or `pixi.toml` by hand.

## Commits

- Use conventional commits: `type(scope): subject`, with a type from
  `cog.toml` (`feat`, `fix`, `perf`, `bench`, `refactor`, `docs`, `test`,
  `build`, `ci`, `chore`, `style`, `revert`).
  `potctl ci cog-check` rejects other types.
- Subject at most 72 characters, in the imperative, no trailing period.
- Wrap the body at 72 columns and say why, not only what.
- Put code identifiers in backticks.
- Use no dashes as punctuation, no `!`, and no breaking change framing in the
  subject or body.
- Keep pull request numbers, commit hashes and ticket ids out of messages and
  documentation.
- Add no trailers (`Co-authored-by`, `Signed-off-by`, tool credits) unless the
  maintainer asks for one.
- One logical change per commit.
- A user visible change needs a towncrier fragment in `docs/newsfragments/`
  (`<slug>.<type>.md`, types in `towncrier.toml`); the `towncrier` job runs on
  every pull request.

## Source headers

Every source file starts with the license header, before includes and
documentation blocks (`#pragma once` goes on the line above it):

```cpp
// MIT License
// Copyright 2023--present rgpot developers
```

Fortran uses `!`; Python and shell use `#` (after any shebang line); Rust uses
`//`.
Documentation style, naming and Doxygen markup are in
`docs/orgmode/contributing/developer/style_guide.org`.
