* What it checks

A binary built on an AVX-512 host, or with a stray ~-mavx2~ or
~-march=native~, dies with SIGILL on a machine that lacks that
instruction set.
This gate decodes every executable section and rejects an instruction
outside the baseline unless the instruction sits in a function the
allowlist names for that feature.

The baseline is x86-64 on x86_64 files and armv8-a on aarch64 files.
~--baseline x86-64-v2~ also accepts SSE3, SSSE3, SSE4.1, SSE4.2 and
POPCNT.
ENDBR (~cet_ibt~) is baseline because it is a NOP on CPUs without CET.
~rdssp~ and ~incssp~ (~cet_ss~) are baseline only in unwinder code.
On aarch64, hint-space instructions (~bti~, ~paciasp~, ~autiasp~ and
the other pointer-authentication hints) are baseline for the same
reason: they do not trap on armv8.0.
SVE, SVE2, SME, LSE atomics, FCMA, dot-product, I8MM, BF16 and the
other named extensions are not baseline.
A macOS arm64 Mach-O slice is the exception for ~lse~ and ~rcpc~.
Apple Silicon is the only CPU that can load that slice, and both
features are architectural there.
The compiler lowers C++ atomics to ~ldadd~ and ~ldapr~ in ordinary
functions, so those two names are baseline for that slice and are
printed in the report.
An ELF built for armv8-a still treats them as above the baseline.

There is no emulation.
The gate does not run the instructions.
Runtime path tests belong in each repository, and per-microarchitecture
runs belong on real nodes through EESSI
(Dröge et al., Softw. Pract. Exp. 53, 176 (2023),
doi:10.1002/spe.3075).

* Why the allowlist is per function

A package-level allowlist, as in the EESSI auditor, says that some
object in the package may use AVX-512.
That does not say which object.
A kernel compiled with ~-march=native~ would pass as long as one
dispatched file in the same package was allowed to.

Our dispatched kernels are known functions
(Páll and Hess, Comput. Phys. Commun. 184, 2641 (2013),
doi:10.1016/j.cpc.2013.06.003, is the cluster-pair layout those kernels
follow).
An above-baseline instruction passes only when the demangled name of
the enclosing function matches a regex whose feature list contains
that feature.
Third-party code that dispatches inside its own binary, and does not
expose one symbol per kernel, is allowed by file path.
The path and the reason are written in the allowlist.
Nothing is skipped silently.

A file with no function symbols fails closed (~no symbols~).
Release jobs must audit unstripped artefacts.
~.symtab~ is used when it contains functions, otherwise ~.dynsym~.

* Running it

Python 3.10 or newer.
Dependencies are pinned in =requirements.txt= (iced-x86 for x86_64,
capstone for aarch64 and for Mach-O, pyelftools, cxxfilt).
The audit job itself runs on an x86_64 runner and decodes both
architectures there.

#+begin_src bash
python ci/isa-audit/isa_audit.py PATH --allow rgpot/isa-allow.toml
python ci/isa-audit/isa_audit.py wheel.whl --allow isa-allow.toml --json report.json
#+end_src

=PATH= may be an ELF, a Mach-O, a directory, or a =.whl= (unzipped to a
temporary directory).
A later file with the same bytes is not decoded again.
The report counts those duplicates.
The text report lists files audited, instructions decoded, per-feature
counts inside allowed functions, and one line per violation:

: VIOLATION file symbol address mnemonic feature

The process exits 1 when any violation is printed.
A Mach-O slice this parser cannot read is printed as =not audited= and
fails the run.

* Allowlist

#+begin_src toml
baseline = "x86-64"

[[allow]]
symbol = '^hwy::N_AVX3(_ZEN4|_SPR|_DL)?::'
features = ["avx512f", "avx512vl", "avx512dq", "avx512bw", "avx2", "fma", "bmi1", "bmi2", "f16c", "popcnt", "lzcnt"]
reason = "Highway dynamic dispatch target"

[[vendored]]
path = ".*libopenblas.*"
features = ["avx512f", "avx2", "fma"]
reason = "DYNAMIC_ARCH"
#+end_src

=symbol= and =path= are Python regular expressions, searched against
the demangled name and the file path.
Feature names are the iced-x86 CPUID names in lower case
(=avx512f=, =avx2=, =cmpxchg16b=) or the aarch64 names this tool prints
(=sve=, =sve2=, =sme=, =lse=, =fcma=, =dotprod=, =i8mm=, =bf16=).
Rust v0 and legacy names and Itanium C++ names are demangled before
the match.
Crate disambiguators are omitted.

rgpot ships no dispatched kernel, so =rgpot/isa-allow.toml= has only
vendored entries: OpenBLAS (=DYNAMIC_ARCH=), libgfortran matmul
variants, libgomp, and libquadmath which is copied in with libgfortran.
An above-baseline instruction in =librgpot= or =_core= is a violation.

* Calling the workflow from another repository

Pin the reusable workflow by commit SHA.
Upload an unstripped artefact from the build job, then:

#+begin_src yaml
jobs:
  audit:
    needs: build
    permissions:
      contents: read
      actions: write
    uses: OmniPotentRPC/rgpot/.github/workflows/isa-audit.yml@<commit-sha>
    with:
      artifact-name: unstripped-libs
      allow-file: isa-allow.toml
      baseline: x86-64
#+end_src

The script is checked out from the pinned workflow commit.
The allowlist is checked out from the caller.
Inside rgpot, =isa-audit-selftest.yml= calls
=uses: ./.github/workflows/isa-audit.yml= on the fixture that must pass.
The negative fixtures (global =-mavx2=, an unlisted target attribute,
a stripped object, an unlisted SVE function) are compiled and checked
in that same workflow, on =ubuntu-latest= and =ubuntu-24.04-arm=.
