i-PI socket server and driver¶

rgpot speaks the i-PI socket protocol in both directions. IPIPot is the server: it sends geometries to an external driver. IPIDriver and the rgpot-ipi-driver program are the driver. They answer a server with an rgpot potential. The server can be i-PI, ASE’s SocketIOCalculator or IPIPot. The protocol is Ceriotti, More and Manolopoulos, CPC 185, 1019 (2014). The i-PI 3.0 paper is Litman et al., J Chem Phys 161, 062504 (2024). The driver reference lists its names.

Wire contract¶

Headers are 12-byte space-padded ASCII. Integers are int32 and floats are float64. Both are in the host byte order, as in the i-PI C wrappers and driver.py. Lengths are bohr, energies are hartree, and forces are hartree per bohr. The cell and its inverse are 3x3, with lattice vectors in the columns. Internally rgpot stores lattice vectors as rows, and both sides transpose. The virial is the extensive tensor in hartree, W_ij = sum_a F_a,i * r_a,j. It is not divided by the cell volume. The rgpot Cauchy stress is sigma = -W / V in eV/Angstrom3. The protocol carries no species, so each driver keeps its own list.

Server: IPIPot¶

IPIPot binds a UNIX or TCP socket, accepts one driver, and sends geometries. The driver can be CP2K, Quantum ESPRESSO, FHI-aims, LAMMPS or i-pi-py_driver. It connects and returns energy, forces and a virial.

Address¶

The constructor takes IPIConfig::address and timeout_s in seconds. The default timeout is 30 seconds. The socket is bound in the constructor. The driver is accepted on the first force call. timeout_s is one budget per force call. It covers waiting for the driver to connect and the force exchange.

  • unix:/absolute/path binds that path.

  • unix:<name> binds /tmp/ipi_<name>, the i-PI default prefix. i-pi-py_driver -u -a <name> then connects. The name must not contain /. On macOS the address length is set, which the kernel requires.

  • tcp:<host>:<port> listens on that IPv4 host and port.

  • tcp:<port> listens on 127.0.0.1.

  • Port 0 asks the kernel for a free port. endpoint() reports the chosen port.

The constructor throws std::invalid_argument for a malformed address. It does the same for a UNIX path too long for the socket address. It does the same for a timeout_s that is negative or not finite. A socket that cannot be bound throws std::runtime_error.

potserv (built with -Dwith_rpc=true) takes the same strings after IPI:.

./build/CppCore/potserv 12345 IPI:unix:rgpot
./build/CppCore/potserv 12345 IPI:tcp:127.0.0.1:31415

Messages¶

A singular cell throws std::invalid_argument before a driver is accepted. A force call sends STATUS until the driver reports READY. It tries at most eight times. NEEDINIT is answered with INIT, with bead id 0 and an empty init string. The server then writes POSDATA and GETFORCE in one payload. It reads FORCEREADY back. These throw std::runtime_error and close the connection. A timeout, a disconnect or an unexpected header. A driver that is not READY after eight STATUS messages. An atom count that differs from the geometry. The next force call accepts a new driver. The destructor sends EXIT when a driver is connected.

Python¶

With RGPOT_HAS_IPI the extension has rgpot.IPIPot(address, timeout_s=30.0). has_ipi is always present. The address forms are those above. __call__ takes positions and the box in Angstrom. It returns the energy in eV, the forces in eV per Angstrom and the variance. The stress() method returns the last Cauchy tensor in eV/Angstrom3. Its shape is (3, 3), and it is None before a successful call. A bad address raises ValueError. A timeout or protocol failure raises RuntimeError.

import numpy as np
import rgpot

pot = rgpot.IPIPot("tcp:0", timeout_s=0.2)
assert pot.stress() is None
try:
    pot(np.zeros((1, 3)), [1], np.diag([10.0, 10.0, 10.0]))
except RuntimeError as err:
    print(err)  # no driver connected within timeout_s

Driver: rgpot-ipi-driver¶

rgpot-ipi-driver connects to a server and answers it with a potential. Any name that engines/pot_spec.hpp builds works, and --list prints them. The socket flags follow i-pi-py_driver: -u, -a, -p, -S, -m, -o. The species come from --species or from a structure file.

rgpot-ipi-driver --pot "LJ u0 0.0104 psi 3.40 cutoff 8.5" --species 'Ar*108' -u -a rgpot
rgpot-ipi-driver -m EAMTable -o file=Cu_u3.eam --species-from start.xyz -p 31415
rgpot-ipi-driver -m EAMAl --species 'Al*108' --cutoff 7.1 --stress-step 1e-5 -u -a al

The driver retries the connection for --connect-timeout seconds. So it can start before the server listens. It answers STATUS, INIT, POSDATA and GETFORCE until EXIT. A server that closes the socket between messages also ends it. ASE does that. The exit code is then 0. Every POSDATA must carry as many atoms as the species list.

Cells¶

A singular cell (zero volume) is an open cluster. ASE sends one for pbc=False. The driver evaluates it in a cube at least 100 Angstrom wide. The cube is also wider than twice the cluster extent plus the cutoff. A periodic cell no wider than twice the cutoff is tiled before evaluation. The cutoff is the potential’s own (LJ, Morse, SuttonChen) or --cutoff. RgpotCalculator handles small and open cells the same way.

Virial¶

The virial is W = -sigma V in hartree for a potential that reports stress. For one that does not, --stress-step H takes a central difference. It strains positions and cell together by H. That costs twelve extra evaluations per geometry. Without it the virial is zero. The extra string is a small JSON object, such as {"virial": "kernel", "virial_units": "hartree"}. --no-extras sends an empty string.

ASE¶

ASE’s SocketIOCalculator is a server. It can launch the driver itself.

import subprocess

from ase.build import bulk
from ase.calculators.socketio import SocketIOCalculator

atoms = bulk("Ar", "fcc", a=5.26, cubic=True).repeat(3)
cmd = ["rgpot-ipi-driver", "--pot", "LJ u0 0.0104 psi 3.40 cutoff 8.5",
       "--species", f"Ar*{len(atoms)}", "-u", "-a", "rgpot"]
with SocketIOCalculator(unixsocket="rgpot",
                        launch_client=lambda *a, **k: subprocess.Popen(cmd)) as calc:
    atoms.calc = calc
    print(atoms.get_potential_energy(), atoms.get_stress())

ASE uses CODATA 2014 constants and rgpot uses CODATA 2018. So the results agree with RgpotCalculator to about 1e-8 relative. The ipi_driver_ase meson test checks LJ and EAM-Al on sheared cells. It also checks an LJ cluster, TCP and the usage errors.

i-PI¶

An i-PI input names the driver’s socket in ffsocket. The driver then serves every bead.

<ffsocket name='rgpot' mode='unix' pbc='false'>
  <address>rgpot</address>
</ffsocket>

i-pi input.xml &
rgpot-ipi-driver --pot "LJ u0 0.0104 psi 3.40 cutoff 8.5" --species-from init.xyz -u -a rgpot

The ipi_driver_ase test runs a two-bead NVE run like this when i-pi is on PATH.

C++¶

IPIDriver takes an IPIDriverConfig and any evaluation function. The driver reference has an example. IPIPot and IPIDriver in one process reproduce a direct evaluation. The IPIDriverTest cases check energy, forces and virial to 1e-12 relative.

Overhead¶

rgpot-ipi-bench times one force call through IPIPot and IPIDriver. It compares a UNIX socket and TCP on the loopback with a direct call. Server and driver run in one process, one thread each. Each case is the median over five runs of the per-call median. The geometries are displaced fcc blocks: LJ argon (cutoff 8.5 Angstrom) and Foiles copper EAM from CppCore/tests/data/eam_table/Cu_u3.eam. The 4.95 Angstrom cutoff of the copper table exceeds half of any 64-atom cell. So that row is missing.

./build/engines/rgpot-ipi-bench --eam CppCore/tests/data/eam_table/Cu_u3.eam

Build¶

Meson with_ipi is a feature option. auto compiles the server, the driver and the program on POSIX hosts. It leaves them out on Windows. -Dwith_ipi=enabled is an error on Windows. CMake RGPOT_WITH_IPI defaults on except on Windows. ON there is an error. The compile definition is RGPOT_HAS_IPI. rgpot-ipi-driver is installed with the other engine programs. rgpot-ipi-bench is not installed.
