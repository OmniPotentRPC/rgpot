C++ API¶

The C++ API in include/rgpot/ wraps the C ABI of rgpot-core in move-only handles. rgpot/rgpot.hpp includes errors.hpp, potential.hpp and types.hpp, and rpc_client.hpp only when RGPOT_HAS_RPC is defined. It does not include CppCore/rgpot/Potential.hpp; each potential header (for example rgpot/LennardJones/LJPot.hpp) brings in rgpot::PotentialBase and rgpot::Potential. Most wrapper methods pass the C status code to an internal check that throws rgpot::Error for any status other than RGPOT_SUCCESS. The exceptions are stated in each entry: invalidate_hvp and reset_hvp_counts call C functions that return nothing, and the factories and the InputSpec and CalcResult constructors check nothing. The wrappers call the C functions of rgpot-core, which a Meson build links only with -Dwith_rust_core=true. Meson defines RGPOT_HAS_RPC only when with_rust_core is on together with with_rpc or with_rpc_client_only.

The handles do not convert units. Positions, cell, energy and forces are in the units of the wrapped potential. The built-in potentials use Angstrom, eV and eV/Angstrom (CppCore/rgpot/units.hpp).

include/rgpot/errors.hpp¶

rgpot::Error¶

explicit Error(const std::string &msg);
Inputs

msg, the text that what() returns.

Units

none.

Outputs

an exception derived from std::runtime_error.

Errors

none; the constructor has no failure path.

The wrappers build msg from a category prefix and the rgpot_last_error() text, or “unknown error” when that pointer is NULL. The prefixes are “invalid parameter: “ for RGPOT_INVALID_PARAMETER, “RPC error: “ for RGPOT_RPC_ERROR, “buffer size error: “ for RGPOT_BUFFER_SIZE_ERROR, and “internal error: “ for RGPOT_INTERNAL_ERROR and any other code. Every category throws the same type, rgpot::Error.

rgpot::InputSpec¶

InputSpec(size_t n_atoms, double *pos, int *atmnrs, double *box);
InputSpec(std::vector<double> &positions, std::vector<int> &atmnrs, double *box);
Inputs

n_atoms; pos or positions, 3*n doubles, row-major xyz per atom; atmnrs, n atomic numbers; box, 9 doubles, the cell vectors as rows. The vector overload takes n as positions.size() / 3.

Units

positions and cell in the length unit of the potential (Angstrom for the built-in potentials); atomic numbers and counts have none.

Outputs

a move-only object holding an rgpot_force_input_t with non-owning DLPack tensors over the caller’s arrays. The arrays are borrowed, not copied, and must outlive the object. The destructor frees the tensor metadata, not the arrays.

Errors

none; nothing is checked. The vector overload does not compare atmnrs.size() with n. NULL pointers are stored as given and surface as errors from the call that reads them.

rgpot::PotentialHandle::from_impl¶

template <typename Impl> static PotentialHandle from_impl(Impl &impl);
template <typename Impl>
static PotentialHandle from_impl(Impl &impl, size_t n_atoms,
                                 const int32_t *atomic_numbers,
                                 const double *box_matrix,
                                 const double *bounds_low = nullptr,
                                 const double *bounds_high = nullptr);
Inputs

impl, an object with forceImpl(const rgpot::ForceInput &, rgpot::ForceOut *); the caller keeps ownership and must keep it alive while the handle lives. The second overload also takes n_atoms, atomic_numbers (n values), box_matrix (9 doubles) and optional bounds (3*n doubles each, default -50 and 50 per coordinate when NULL); rgpot_potential_new_eindir copies them.

Units

positions, cell and bounds in the length unit of impl.

Outputs

a handle whose callback calls impl.forceImpl and returns the forces as a new owning [n, 3] tensor. When Impl has hessianVectorImpl, it is registered as the analytic Hessian-vector product.

Errors

none thrown by the factory. When n_atoms * 3 overflows, the second overload returns a handle holding NULL, and later calls on it throw rgpot::Error (“invalid parameter”). At calculation time an exception from impl.forceImpl becomes RGPOT_INTERNAL_ERROR, and missing positions become RGPOT_INVALID_PARAMETER; the calling method throws rgpot::Error. The exception’s own message is dropped.

The trampoline copies energy, variance and forces from ForceOut; it does not pass stress through.

rgpot::PotentialHandle::hvp¶

void hvp(const InputSpec &input, const double *direction, double *hv_out,
         double step = 0.0, rgpot_hvp_scheme_t scheme = RGPOT_HVP_AUTO) const;
std::vector<double> hvp(const InputSpec &input,
                        const std::vector<double> &direction,
                        double step = 0.0,
                        rgpot_hvp_scheme_t scheme = RGPOT_HVP_AUTO) const;
Inputs

input, the geometry; direction, 3*n doubles laid out like the positions; hv_out, room for 3*n doubles that must not overlap direction; step, the displacement length, where 0 selects RGPOT_HVP_DEFAULT_STEP; scheme, one of RGPOT_HVP_AUTO, RGPOT_HVP_FORWARD, RGPOT_HVP_CENTRAL, RGPOT_HVP_ANALYTIC.

Units

step in the length unit of the positions; the product is the Hessian (energy per length squared, eV/Angstrom2for the built-in potentials) times direction.

Outputs

the Hessian-vector product, 3*n doubles: written to hv_out, or returned as a new vector by the second overload.

Errors

throws rgpot::Error when rgpot_potential_hvp returns a non-success status: NULL pointers, an unknown scheme, a negative or non-finite step, a non-finite direction value, overlapping buffers, or RGPOT_HVP_ANALYTIC with no analytic callback give “invalid parameter”; a failing force callback gives the category of its status. The vector overload throws rgpot::Error (“invalid parameter: direction must hold 3 * natomsvalues”) when direction.size() is not 3*n.

With RGPOT_HVP_FORWARD, k products at one geometry make k+1 force calls.

CppCore/rgpot/CalculatorGroup.hpp¶

A calculator is one independent evaluation, such as a NEB image or a dimer end; the ranks of one calculator share a subcommunicator. librgpot never links MPI. The MPI side is librgpot_mpi, which bindCalculators and calculatorsUseMpi load with dlopen on first use (Meson option -Dwith_mpi=enabled). Until that library is loaded, every function below behaves as a process of one calculator with one rank. Running under MPI is described in MPI.

rgpot::bindCalculators¶

CalculatorGroup bindCalculators(int ranks_per_calculator);
Inputs

ranks_per_calculator; 0 or less means one calculator for the whole world.

Units

none.

Outputs

the CalculatorGroup of this rank, also kept for thisCalculator. With librgpot_mpi loaded it is collective on MPI_COMM_WORLD, calls MPI_Init when MPI is not up yet, and splits the world. Without it, 1 or 0 or less gives index 0 with one rank, and any other value gives index -1. Registered hooks and communicator adopters are then called; a negative result from any of them sets index to -1.

Errors

no exception; failure is reported as index -1. Index is -1 when the world size is not a multiple of ranks_per_calculator or is smaller than it, and when a hook or adopter refuses. After a bind, a call whose argument equals the stored ranks per calculator returns the stored group. Any other argument returns a group with index -1 and leaves the stored group unchanged. An argument of 0 or less is compared as its resolved value (the world size, or 1 without MPI), so repeating bindCalculators(0) returns the stored group.

Example¶

The build in this tree is configured with with_rust_core off, so the rgpot-core symbols that the handles call are not linked; the example is only compiled.

#include <cstdio>

#include "rgpot/LennardJones/LJPot.hpp"
#include "rgpot/rgpot.hpp"

int main() {
  rgpot::LJPot lj;
  auto pot = rgpot::PotentialHandle::from_impl(lj);

  double pos[] = {0, 0, 0, 1.1, 0, 0};
  int atm[] = {1, 1};
  double box[] = {10, 0, 0, 0, 10, 0, 0, 0, 10};
  rgpot::InputSpec input(2, pos, atm, box);

  try {
    rgpot::CalcResult result = pot.calculate(input);
    std::vector<double> forces = result.forces_vec();
    std::printf("E = %.6f, Fx0 = %.6f\n", result.energy(), forces[0]);
  } catch (const rgpot::Error &e) {
    std::printf("%s\n", e.what());
    return 1;
  }
  return 0;
}
