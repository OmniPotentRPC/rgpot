UmaPot takes the input dtype of a package that records neither `pos_dtype` nor `model_dtype` from the dtype checks in its AOTInductor wrapper source, instead of assuming float32. A float64 package without those keys used to get float32 positions, cell and cell offsets, and failed inside the graph or read them as doubles. A wrapper source whose `pos` check is missing or names a dtype other than float32 or float64, or whose `cell` or `cell_offsets` check disagrees with `pos`, throws `UmaContractError` when the package loads. Either dtype key still wins. A package refused at load is now refused on every call, not only the first.
