`rgpot::setThreadCount`, `rgpot::clearThreadCount`, `rgpot::ThreadCount` and `PotentialBase::setThreadCount` set the thread count for a call. They are opt-in: with none of them set, `threadsRequested` is still `OMP_NUM_THREADS` (unset, empty or below 1 is one thread) and a long-range call still sizes its team from the OpenMP pool. A `ThreadCount` already on the stack is not replaced by a potential's own setting. A count below 1 throws `std::invalid_argument`. Without OpenMP the request is reported by `explicitThreadCount` and the call stays one thread.

A classical row or cell team still gives each slice a contiguous range of atoms, one slice per thread, and each atom keeps the whole of its own row. Those rows are added in atom order, which does not depend on how many slices there were, and one thread still walks the single slice it walked before. Dispersion and the D3 and D4 pair reductions accumulate one partial per fixed chunk, not one per thread, and fold the partials with a Neumaier sum in chunk order, on every thread count including one. The PME kernel energy uses the same rule: the partial count follows the mesh, not the team.
