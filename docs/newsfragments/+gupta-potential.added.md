Added `GuptaPot` (`PotType::Gupta`), wrapping the Cleri-Rosato Gupta potential across the C++ `Potential` interface (with periodic minimum-image support, Cauchy stress, per-atom energy/virial, staged evaluation, and `rgpot_gupta_energy_forces` C ABI), the `pot_spec` / classical engine / `potserv` `"Gupta"` name, and Python/ASE `rgpot.GuptaPot` (`RgpotCalculator("gupta", ...)`). Coincident atoms are not a finite minimum, and a non finite coordinate has no separation, so `GuptaPot` throws `std::invalid_argument` (`ValueError` in Python) for either. The bare kernel `rgpot_gupta` does not check: it returns +infinity for a coincident pair and a NaN coordinate stays NaN. Zero hopping stays finite.
