A Windows `librgpot` DLL exports the whole public C ABI. Before, it exported the version, the ReducedPair and Sutton-Chen functions and the C++ layout stamp, and none of the neighbour-list, MD session, fast pair list or external-potential functions. The public C headers mark their functions with `RGPOT_API` from `rgpot/rgpot_api.h`, and the fast pair list names reach the DLL through a module definition file. On Windows the engines that call only the C ABI link the DLL. `lj_eval`, `pot_spec` and the drivers built on them link the static archives instead, because the DLL exports no C++ class. The `abi_symbols` test runs on Windows and reads the DLL export table with `dumpbin` or `objdump`, and its baseline now lists every `RGPOT_API` function.
