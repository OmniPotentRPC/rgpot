`XTBDlopen` and `MetatomicDlopen` now have `setThreadCount`, `clearThreadCount` and `threadCount`, so a host can treat them like the other potentials. The count is recorded and nothing more: the engine C ABIs have no call that takes a thread count, and the threads of libxtb and torch belong to their own runtimes, which do not read the rgpot count, so the evaluation is the same at every setting. Set `OMP_NUM_THREADS` in the environment the engine starts in to size those runtimes. `setThreadCount` throws `std::invalid_argument` for a count below 1.
