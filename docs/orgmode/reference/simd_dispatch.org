* SIMD paths and dispatch

LJ, Morse, EAM, and the orthorhombic periodic fold select an instruction set at
run time through Google Highway.
The same source is compiled for SSE2, SSE4, AVX2, AVX3,
AVX3_ZEN4, NEON, SVE, SVE2, SVE_256, RVV, and Highway's EMU128.
SSE2 is the static baseline on x86-64.
A machine runs the best target it supports.
A target the CPU cannot execute is not a pass.
It was not exercised.

** Selection

=rgpot::simd::chosen_target_name()= returns the name of the target this process
will use.
The names are =scalar=, =sse2=, =sse4=, =avx2=, =avx3=,
=avx3_zen4=, =neon=, =sve=, =sve2=, =sve_256=, =rvv=, and =emu128=.
=RGPOT_SIMD= is read once, inside the call that caches the choice.
=scalar= forces the portable kernel.
=sse4=, =avx2=, =avx3=, =avx3_zen4=, =neon=, =sve=, and =sve2= request that
target.
=sse2=, =sve_256=, =rvv=, and =emu128= are accepted as well.
An unknown name is ignored.
A known name the CPU cannot run falls back to =scalar=.

Build with =-Dwith_highway=disabled= and every kernel stays on the scalar path.
=auto= uses libhwy 1.2 or newer when it is installed, and the bundled Highway
1.2 wrap otherwise.

** Bit identity

Atom i's energy, force, and virial go through a fixed width of 8.
Eight partial sums are added as (p0+p4), (p1+p5), (p2+p6), (p3+p7), then those
pairs, then the two results.
The force on atom j is subtracted in neighbour order.
Morse and EAM evaluate the fdlibm =e_exp= polynomial.
The scalar target calls =rgpot::simd::exp=.
Each vector lane replays that function: the same constants, the same multiplies
and adds, and no fused multiply-add.
The pair loop that consumes those lanes is compiled into the target, so the
choice of instruction set is one indirect call per force evaluation.
The LJ loop is vectorized for the round fold and for the coded fold.
The coded fold is the list used when the cutoff plus the skin fits in half a
box.
The orthorhombic fold is a vector loop as well.
No kernel uses a fused multiply-add.
The project passes =-ffp-contract=off= (or =/fp:precise=) to C, C++, and
Fortran, including the vendored vesin and Lepton sources.
A CI job builds the same inputs with =-march=x86-64-v3= and checks that the
SHA-256 of the LJ, Morse, and EAM results matches the default build.

The orthorhombic fold matches =visit_round= for finite in-range values: half
away from zero.
A non-finite lane contributes a zero image index so the conversion to an integer
is defined.
=MinimumImage= works in double.
A cell whose condition estimate would spend more than half the significand is
Minkowski-reduced, and the closest image is taken in that basis.
Nguyen and Stehlé, ACM Trans. Algorithms 5, 46 (2009),
doi:10.1145/1597036.1597050.
A reduced basis that is still too ill-conditioned searches the 27 images with
coefficients in {-1, 0, 1}.
Singular and non-finite cells throw.
An image index that does not fit in a 64-bit integer throws.

** Speed

LJ uses four lanes.
Eight-wide LJ was slower where it was timed.
The neighbour coordinates are not a contiguous vector load.
A 512-bit polynomial did not hide that load.
Morse and EAM stay eight wide because the exp does.
The scalar target is compiled without auto-vectorization.
A debug build and a release build then hash the same bytes.
That target calls the in-house exp, not libm. libm on this class of host picks
an FMA implementation at run time.
Matching the in-house bits forbids that call.
It also forbids contraction.
The scalar target can sit below the pre-dispatch loop on the exp kernels.
The two-lane SSE targets can as well.
AVX2 and AVX3 run the vector exp.
Those are the paths that clear that loop.

** What is not dispatched

The Eigen adapter only copies layouts.
=EIGEN_DONT_VECTORIZE= is set there.
The benchmark host's release build copied the 4000-atom coordinate buffer in
0.032% of one LJ force call on that buffer, which is under 5%, so Eigen is not a
separate vectorized path.
BLAS and LAPACK stay in their own libraries.
Fortran pots are compiled for the build machine's baseline and are not
multi-compiled.
Machine-learning engines are external.
Vendored Lepton is built without =LEPTON_USE_JIT=.

Highway's AVX3_DL, AVX3_SPR, and the reserved AVX10.2 bit are not compiled.
This change has no benchmark that would justify adding them.

** chosen_target_name

=rgpot::simd::chosen_target_name()= takes no arguments and returns a C string.
The pointer stays valid for the life of the process.
It names the target selected for this process, after =RGPOT_SIMD= has been
applied.
