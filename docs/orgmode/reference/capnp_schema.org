* Cap'n Proto schema

This page is generated by =docs/gen_capnp_reference.py= from the schema the
build compiles, which is =CppCore/rgpot/rpc/Potentials.capnp= with the
diffs of =CppCore/rgpot/rpc/local/series= applied.
Change a comment in the schema, then run the script again; do not edit this
page.

Cap'n Proto names a field, union arm, enumerant or method on the wire by its
ordinal, so a row keeps its ordinal for good.
The type column is as written in the schema, and the default column is empty
when the schema gives none (zero, empty or false by the Cap'n Proto rule).
A union arm is written =name @N :Type=; exactly one arm is set.
A row that reads "No comment in the schema" has none upstream, so the
comment has to be added to the pinned schema before this page can say more.
The meaning of each =PotentialConfig= arm and the ordering of the overlay are
in :doc:`potential_config`.

*** struct PotentialSpec

One backend, named and configured, as a value that can be carried inside another backend's configuration.
Backend selection is otherwise a property of which engine library a host dlopens, which works while a potential is a leaf.
A learning surrogate is not a leaf: it wraps an oracle and has to say which one and how it is configured, so the choice has to travel on the wire rather than in the host's loader.
This is that value, one arm per params struct already in this file.
Purely additive: no existing field is renumbered, so a reader that does not know this struct is unaffected.

*** struct GprParams

Learning-surrogate arm: a Gaussian process that answers where its posterior is resolved and calls an oracle where it is not.
The oracle is a nested PotentialSpec rather than a callback, so a host that selects this backend does not also have to supply ground truth through a side channel.
That is the difference between an engine eOn can load and one eOn can use: its GenericEngineLoader resolves create/destroy/force and never calls set_callbacks, so an engine that expects its oracle by callback gets none.
The gate is two-sided and stated in multiples of the model's own likelihood noise rather than in absolute energy, so it transfers across systems.

One chunk. first and second have the same length. shift has 3 times that length when shifts were requested, vector has 3 times that length, distance has that length. mask is one byte per pair, 0xff for a pair list and the low four bits for a cluster. more is true when a later chunk exists. next is the cursor to send for that chunk. status 0 is success. message is a sentence when status is not 0.
The lists are empty in that case.
