* Engine plugin ABI

=CppCore/rgpot/engine_c_abi.h= declares the functions a host calls to drive an
engine shared library through =dlopen= and =dlsym=.
The host selects the backend by the library it opens.
The configuration is a versioned binary message defined by each engine.
The core engines use a Cap'n Proto flat-array message whose root is the engine's
params struct in =Potentials.capnp=.
The potlibc engine accepts =RgpotPotlibcConfigV1= and =RgpotPotlibcConfigV2=
from
=rgpot/potlibc_engine.h=, and the coupled-well engine accepts =RgpotCoupledWellConfigV1= and =RgpotCoupledWellConfigV2= from =rgpot/coupled_well_engine.h=.
Positions and cells are in Angstrom, energies in eV and forces in eV/Angstrom.
A cell is nine doubles in row-major order.

Status codes are three-valued. 0 is success.
A positive value means the evaluation failed at this input and the caller may
back off.
A negative value means the instance is unusable.
The engines in this repository return 1 for an invalid argument, 2 when the
evaluation or the setting failed (the reason is in =rgpot_engine_last_error=),
and 3 when the backend does not support the operation.
They return -2 (=RGPOT_ENGINE_ERR_LOCK=, minor 8) when acquiring an engine or
handle lock fails.
=rgpot_engine_force= and =rgpot_engine_force_batch= also return the nonzero code
of the host's coordinate transform.

To open, build and test an engine, see
[[file:../howto/engine-plugins.org][Open, build and test engine plugins]].

** Libraries

=CppCore/rgpot/engine/EngineTable.cc= implements every function the engine
libraries export except =rgpot_engine_abi_stamp=, for any =PotentialBase=.
=CppCore/rgpot/engine/EngineAbiStamp.cc= defines =rgpot_engine_abi_stamp=.
Every engine plugin, including the standalone ones that do not use the table,
adds that file, so all of them report the same ABI major, minor and layout
revision.
Each library adds one file that defines =rgpot::engine::create= (build the
potential from the params message) and =rgpot::engine::backend_name=.

=BuiltinParams.name= is compared in lower case.
For dxtb, =BuiltinParams.library= may name the Python executable; otherwise
=RGPOT_DXTB_PYTHON= and then =python3= select it.
The first of these that is set is the only one tried.
Creation starts one worker process and imports Python, Torch and dxtb once.
Force and HVP calls use a typed binary stream to that same process, so each call
pays pipe serialization and two process crossings but no Python startup.
The worker rebuilds its calculator only when the element sequence or
configuration changes.
The Metatomic and XTB libraries also export their own tables
(=rgpot_mta_*=, =rgpot_xtb_*=).
NWChem and CPMD keep the prefix-parameterized profile ABI that =NWChemPot= and
=CPMDPot= load, and MOPAC keeps =mopac_c_abi.h=.
The plugin interface in =include/rgpot/plugin.h= is a separate family. tblite,
dftd3, dftd4, ExprPot, XcKernel and CP2K have no engine library.

Every library above except
=libpotlibc_engine= and =libcoupled_well_engine= exports =rgpot_engine_force_batch=,
=rgpot_engine_hvp=, =rgpot_engine_taylor_jet=, =rgpot_engine_abi_stamp=,
=rgpot_engine_abi_compatible=, =rgpot_engine_name=, =rgpot_engine_version=, =rgpot_engine_model_digest=,
=rgpot_engine_caps=,
=rgpot_engine_last_error=, =rgpot_engine_set_num_threads=, =rgpot_engine_set_charge_spin=, =rgpot_engine_select_orbitals=,
=rgpot_engine_copy_orbitals=, =rgpot_engine_last_components=,
=rgpot_engine_component_name=, =rgpot_engine_set_cache= and
=rgpot_engine_cache_counts=.
Only =libcomposite_engine= has components; the others report none.
=libpotlibc_engine= and =libcoupled_well_engine= export the stamp,
compatibility, name, version, caps, last-error, analytic-HVP and batch symbols;
they omit the model digest, setting and component symbols.
=libpotlibc_engine= serves a batch natively with one =potlibc_evaluate= call,
and =libcoupled_well_engine= reports =reentrancy= 0.
Both write nothing to the output buffers of a batch that fails.
None of them exports =rgpot_engine_model_state=, =rgpot_engine_set_callbacks=,
=rgpot_engine_hint=,
=rgpot_engine_neighbor_options= or =rgpot_engine_unload_policy=.

** Persistent result cache and evaluation counts

Probe for =rgpot_engine_set_cache= and =rgpot_engine_cache_counts= when loading
a plugin.
Pass an engine handle and a database directory to the setter before submitting
force calls.
A cache-enabled build opens or creates the directory.
The handle owns the open database until detachment (a null path) or destruction.

Each stored result is keyed by the potential type, a fingerprint of the
potential's parameters, and the geometry.
A potential that overrides its parameter fingerprint gets a new key whenever a
setting that changes its output changes.
The metatomic engine does this for its model path, device, length unit, dtype,
determinism policy, task name, extras and every other setting the model sees.
Calling =rgpot_engine_set_charge_spin= on it changes the fingerprint, so the
next query is a miss that computes under the new charge and spin.
Returning to an earlier charge and spin serves the earlier results again.
Use a separate directory for each model when the engine does not fingerprint its
parameters.

The key is a fixed 64-bit hash, stored as one version byte followed by eight
little-endian bytes.
The key layout does not depend on the width of =size_t= on the host.
Keys written on a 64-bit little-endian host keep their bytes.

The database has no size cap and never evicts on its own.
Its size is bounded by the number of distinct geometries that the caller
submits.
To bound it, detach the cache and delete the directory, or attach a fresh
directory.
Deleting the directory discards every stored result and does not corrupt a later
attachment.
The ABI has no call that sets a cap.

Read the two unsigned 64-bit counters after all requests in a phase return.
=computed= counts geometry results produced by the kernel.
=served= counts geometry results supplied by the cache.
One successful batch can contribute to both counters.
Take differences between snapshots to measure a phase.
Attaching an existing database starts both counters at zero and retains its
stored results.
A count query returns status 3 when the handle has no active cache.
Older plugins can omit the symbols.
Record counters as unavailable in both cases.

On Windows the engine opens the path as UTF-8.
A caller must pass a path that is valid Unicode.
The Rust loader refuses any other path with an invalid-argument error.
On other platforms the loader passes the path bytes unchanged.

*** =rgpot_engine_set_cache=

#+attr_rgpot: signature
#+begin_src c
int rgpot_engine_set_cache(RgpotEnginePot *pot, const char *path);
#+end_src

- Inputs :: a handle and a database path, or a null path to detach.
  The path is UTF-8 on Windows.
- Units :: none.
- Outputs :: a successful call replaces the current attachment.
  Detaching leaves the stored results on disk.

#+end_src

- Inputs :: none.
- Units :: none.
- Outputs :: nonzero when the engine can create instances; the engines in this

- Errors :: none; the call cannot fail.

Optional symbol.

*** =RgpotEngineAbiStamp=

- Inputs :: none; a value type.
- Units :: none.
- Outputs :: three =unsigned short= fields:
  =abi_major= (=RGPOT_ENGINE_ABI_VERSION=, 1),
  =abi_minor= (=RGPOT_ENGINE_ABI_MINOR=, 11) and
  =layout_revision= (=RGPOT_ENGINE_ABI_LAYOUT_REVISION=, 1).
- Errors :: none.

The major increments for an incompatible change.
The minor increments for an addition that leaves every existing call valid: a
new optional symbol, or a new field at the end of a size-prefixed structure.
The layout revision increments when an existing structure changes size or field
order.
A host built against minor N runs against an engine of the same major and layout
revision whose minor is at most N; a plugin with a newer minor than the host's
is refused, while an older plugin whose newer optional exports are absent still
loads.
An engine without =rgpot_engine_abi_stamp= is minor 0, layout 1.
Minor 1 added the stamp, =rgpot_engine_caps=,
=rgpot_engine_last_error=, =rgpot_engine_set_num_threads= and =rgpot_engine_set_charge_spin=.
Minor 2 added =rgpot_engine_name=, =rgpot_engine_version=,
=rgpot_engine_model_digest= and the generic table for every backend.
Minor 3 added
=RgpotEngineCaps.orbital_selection=, =RgpotEngineCaps.orbital_copy=,
=rgpot_engine_select_orbitals= and =rgpot_engine_copy_orbitals=.
Minor 4 added =rgpot_engine_hvp= and the trailing =RgpotEngineCaps.analytic_hvp=
field.
Minor 5 added =RgpotEngineComponent=,
=rgpot_engine_last_components= and =rgpot_engine_component_name=.
Minor 6 adds =rgpot_engine_set_cache= and =rgpot_engine_cache_counts=.
Minor 7 adds =rgpot_engine_unload_policy=, =RGPOT_ENGINE_UNLOAD_RESIDENT= and
=RGPOT_ENGINE_UNLOAD_SAFE=.
Minor 11 adds
=rgpot_engine_taylor_jet=, =RgpotEngineDerivativeReport= and the trailing =RgpotEngineCaps.jet_order=
field.
The persistent dxtb engine exports the shared stamp, so it reports the current
=RGPOT_ENGINE_ABI_MINOR=, and it adds no field to =RgpotEngineCaps=.
The version does not cover the Cap'n Proto params schema, the tensor runtime the
engine links, or the model.

** Instances

*** =RgpotPotlibcConfigV1=

- Inputs :: =magic=
  (=RGPOT_POTLIBC_CONFIG_MAGIC=), =version= (=RGPOT_POTLIBC_CONFIG_VERSION_V1=), =atom_count=
  and =surface_id=.
- Units :: =atom_count= is a count; the other fields have no unit.
- Outputs :: passed as the exact 144-byte create message for
  =libpotlibc_engine=.
- Errors :: a length other than 144 bytes, an unknown magic, a =version= other
  than =RGPOT_POTLIBC_CONFIG_VERSION_V1= (the plain error string
  =potlibc config version is unknown=, including when a recompiled version-1
  source passes
  =RGPOT_POTLIBC_CONFIG_VERSION=), an empty or unterminated catalog id, zero atoms for a variable-size surface, or a nonzero count for a fixed-size surface makes =rgpot_engine_create=
  return NULL.

=magic= is at offset 0, =version= at offset 4,
=atom_count= at offset 8 and =surface_id= at offset 16.
=surface_id= has =RGPOT_POTLIBC_SURFACE_ID_CAPACITY= bytes and is
NUL-terminated.
=atom_count= is zero for a fixed-size catalog entry and the requested count for
a variable-size entry.
There is no =size= field and no reserved field.
=RGPOT_POTLIBC_CONFIG_VERSION= is 2, so version-1 sources recompiled against this header must use =RGPOT_POTLIBC_CONFIG_VERSION_V1= and =RGPOT_POTLIBC_CONFIG_V1_SIZE=.

*** =RgpotPotlibcConfigV2=

- Inputs :: =magic=
  (=RGPOT_POTLIBC_CONFIG_MAGIC=), =size= (bytes, at least =RGPOT_POTLIBC_CONFIG_MIN_SIZE=), =version= (=RGPOT_POTLIBC_CONFIG_VERSION=),
  =reserved= (zero), =atom_count= and =surface_id=.
- Units :: =atom_count= is a count; the other fields have no unit.
- Outputs :: passed as the version-2 create message for =libpotlibc_engine=.
- Errors :: an unknown magic, a version other than
  =RGPOT_POTLIBC_CONFIG_VERSION= (the plain error string =potlibc config version is unknown=), a nonzero =reserved=, an empty or unterminated catalog id, zero atoms for a variable-size surface, or a nonzero count for a fixed-size surface makes =rgpot_engine_create=
  return NULL.
  =size < RGPOT_POTLIBC_CONFIG_MIN_SIZE= is refused as a typed size error.
  A message larger than =RGPOT_POTLIBC_CONFIG_MIN_SIZE= is accepted only when
  every unknown trailing byte up to =size= is zero.

=size= is at offset 4 and =version= is at offset 8.
=surface_id= and =atom_count= have the same meaning as in
=RgpotPotlibcConfigV1=.

*** =RgpotCoupledWellConfigV1=

- Inputs :: =magic= (=RGPOT_COUPLED_WELL_CONFIG_MAGIC=), =version=
  (=RGPOT_COUPLED_WELL_CONFIG_VERSION_V1=), =atomic_number=, =reserved= (zero),
  =barrier_energy=, =well_position=, =transverse_spring= and =coupling=.
- Units :: =barrier_energy= in eV, =well_position= in Angstrom,
  =transverse_spring= in eV/Angstrom^2 and =coupling= in 1/Angstrom.
- Outputs :: passed as the exact 48-byte create message for
  =libcoupled_well_engine=.
- Errors :: a length other than the 48 bytes of the structure, an unknown magic,
  a =version= other than
  =RGPOT_COUPLED_WELL_CONFIG_VERSION_V1= (the plain error string =coupled-well config version is unknown=, including when a recompiled version-1 source passes =RGPOT_COUPLED_WELL_CONFIG_VERSION=), a nonzero =reserved=, a non-positive =atomic_number=,
  a =barrier_energy=, =well_position= or
  =transverse_spring= that is not finite and positive, or a =coupling= that is not finite makes =rgpot_engine_create=
  return NULL with the reason in =errbuf=.

=magic= is at offset 0, =version= at offset 4,
=atomic_number= at offset 8, =reserved= at offset 12, =barrier_energy= at offset
16, =well_position= at offset 24, =transverse_spring= at offset 32 and
=coupling= at offset 40.
=RGPOT_COUPLED_WELL_CONFIG_VERSION= is 2, so version-1 sources recompiled
against this header must use
=RGPOT_COUPLED_WELL_CONFIG_VERSION_V1= and =RGPOT_COUPLED_WELL_CONFIG_V1_SIZE=.

*** =RgpotCoupledWellConfigV2=

- Inputs :: =magic= (=RGPOT_COUPLED_WELL_CONFIG_MAGIC=), =size= (bytes, at least
  =RGPOT_COUPLED_WELL_CONFIG_MIN_SIZE=), =version= (=RGPOT_COUPLED_WELL_CONFIG_VERSION=), =reserved0= (zero), =atomic_number=,
  =reserved1= (zero), =barrier_energy=, =well_position=, =transverse_spring= and
  =coupling=.
- Units :: =barrier_energy= in eV, =well_position= in Angstrom,
  =transverse_spring= in eV/Angstrom^2 and =coupling= in 1/Angstrom.
- Outputs :: passed as the version-2 create message for
  =libcoupled_well_engine=.
- Errors :: a =size= below
  =RGPOT_COUPLED_WELL_CONFIG_MIN_SIZE=, an unknown magic, a version other than =RGPOT_COUPLED_WELL_CONFIG_VERSION= (the plain error string =coupled-well config version is unknown=), a nonzero reserved field, a non-positive =atomic_number=,
  a =barrier_energy=, =well_position= or
  =transverse_spring= that is not finite and positive, or a =coupling= that is not finite makes =rgpot_engine_create=
  return NULL with the reason in =errbuf=.
  A message larger than =RGPOT_COUPLED_WELL_CONFIG_MIN_SIZE= is accepted only
  when every unknown trailing byte up to =size= is zero.

=size= is at offset 4 and =version= is at offset 8.
The physical fields have the same meaning as in =RgpotCoupledWellConfigV1=.

The engine evaluates one atom of species =atomic_number= with the energy
=V0 ((x / x0)^2 - 1)^2 + k / 2 (y - alpha x^2)^2=, where =V0=, =x0=, =k= and
=alpha= are the four parameters in order.
The z force and the z row and column of the Hessian are zero, and the cell is
ignored.
See [[file:../howto/coupled-well-engine.org][the coupled-well how-to]].

*** =RgpotEnginePot=

- Inputs :: none; an opaque handle.
- Units :: none.
- Outputs :: returned by =rgpot_engine_create= and released by
  =rgpot_engine_destroy=.
- Errors :: none.

A handle holds the backend potential, its capabilities, the last error message
and the model digest once computed.

*** =rgpot_engine_create=

#+attr_rgpot: signature
#+begin_src c
RgpotEnginePot *rgpot_engine_create(const void *config, size_t config_len,
                                    char *errbuf, size_t errlen);
#+end_src

- Inputs :: =config=, the library's versioned binary message; core engines use a
  Cap'n Proto flat-array message (as produced by =capnp::messageToFlatArray=)
  whose root is their params struct, while
  =libpotlibc_engine= accepts =RgpotPotlibcConfigV1= and =RgpotPotlibcConfigV2=, and =libcoupled_well_engine= accepts =RgpotCoupledWellConfigV1= and =RgpotCoupledWellConfigV2=; =config_len=,
  its length in bytes; =errbuf= and =errlen=, a buffer for the failure reason
  (may be null or 0).
- Units :: none.
- Outputs :: a new handle, or NULL on failure.
- Errors :: returns NULL and writes the reason to =errbuf= (at most =errlen - 1=
  bytes, NUL-terminated).
  A null =config=, a zero
  =config_len= or a length that is not a multiple of 8 gives =rgpot_engine_create(<name>): a word-aligned Cap'n Proto params message is required=.
  An empty =modelPath= (UMA, Metatomic), an unknown =BuiltinParams.name=, a
  malformed message or an exception from the backend constructor gives that
  message.
  A =MetatomicParams.charge= or =spin= the model does not read, other than
  charge 0 or multiplicity 1, gives =rgpot_engine_create(metatomic):= followed
  by the reason =rgpot_engine_set_charge_spin= gives.

Required symbol.
=RgpotPotlibcConfigV1= carries a magic, version, atom count and canonical
surface id and is exactly 144 bytes.
=RgpotPotlibcConfigV2= carries a magic, message size, version, reserved word,
atom count and canonical surface id.
Its atom count is zero for fixed-size surfaces and the exact count for
variable-size surfaces.
A version other than 1 or 2 is reported as the plain error string
=potlibc config version is unknown= or =coupled-well config version is unknown=.
=RgpotCoupledWellConfigV1= carries a magic, version, the accepted atomic number,
one reserved word and the four coupled-well parameters and is exactly 48 bytes.
=RgpotCoupledWellConfigV2= carries a magic, message size, version, two reserved
words, the accepted atomic number and the four coupled-well parameters.
=UmaParams= and =MetatomicParams= carry =intraopThreads= and =interopThreads=
(default 1), which create applies with the rules of
=rgpot_engine_set_num_threads=; a refused inter-op count fails create with the
reason.
=UmaParams.deterministicAlgorithms= turns on deterministic torch algorithms, so
an operation without a deterministic implementation throws.
=MetatomicParams.torchDeterminism= (=fast= or =deterministic=) selects the
=TorchDeterminismPolicy= of the Metatomic potential.
=MetatomicParams.charge=, =spin= (a value below 1 becomes 1) and
=attachSystemExtras= go to the Metatomic potential; see Charge and spin below.
=UmaParams.cacheDir= is the root of the cache the UMA package is unpacked into;
see the UMA unpack cache below.

*** =RgpotEngineDerivativeReport=

- Inputs :: none; the engine fills it in =rgpot_engine_taylor_jet=.
- Units :: =scale= is in the units of the returned jet, eV/Angstrom.
- Outputs :: =tracked= (0 or 1), =operations= (=long long=) and =scale=
  (=double=).
- Errors :: none.

When =tracked= is 1, =operations= times the machine epsilon times =scale= is the
engine's first-order estimate of the roundoff of the returned derivatives; it is
an estimate from an operation count, not a rigorous bound.
For a batch, =operations= is the sum over the systems and =scale= the largest.
When =tracked= is 0, =operations= and =scale= are 0.

*** =RgpotEngineCaps=

- Inputs :: =size=, set by the host to =sizeof(RgpotEngineCaps)= before
  =rgpot_engine_caps=.
- Units :: none.
- Outputs :: =size= (bytes the engine wrote), =reentrancy=,
  =per_image_instances=, =batched=, =periodic=, =stress=,
  =group_collective=, =orbital_selection=, =orbital_copy=, =analytic_hvp= and
  =jet_order=; the flags are 0 or 1.
- Errors :: none.

The fields mirror rgpot's =PotCaps=.
=per_image_instances= asks multi-image methods (NEB) to clone one instance per
image.
=batched= means the backend serves =rgpot_engine_force_batch= natively.
=periodic= means periodic boundary conditions are supported.
=stress= means the backend computes cell stress; the engine ABI has no call that
returns it.
=group_collective= means every rank of a calculator group enters each call.
=orbital_selection= means the backend supports =rgpot_engine_select_orbitals=.
=orbital_copy= means the backend supports =rgpot_engine_copy_orbitals=.
=analytic_hvp= means =rgpot_engine_hvp= returns an exact directional product.
=jet_order= is the highest order =rgpot_engine_taylor_jet= serves, 0 when the
backend has no gradient jet.

=reentrancy= decides how the table admits concurrent =rgpot_engine_force= and
=rgpot_engine_force_batch= calls:

- 0, shared instance: calls run concurrently on one handle (UMA, Metatomic, and
  the coupled-well engine).
- 1, per instance: one call at a time per handle; calls on different handles run
  concurrently (XTB and every potential of the classical engine).
- 2, process serial: one call at a time across all handles of the library in the
  process (MOPAC, NWChem, Skala).

*** =rgpot_engine_taylor_jet=

#+attr_rgpot: signature
#+begin_src c
int rgpot_engine_taylor_jet(RgpotEnginePot *pot, long nSystems, long nAtoms,
                            const double *positions, const int *atomicNrs,
                            const double *directions, long order,
                            double *jet_out,
                            RgpotEngineDerivativeReport *report,
                            const double *boxes);
#+end_src

- Inputs :: =nSystems= systems sharing one composition (=atomicNrs=, =nAtoms=),
  as for =rgpot_engine_force_batch=.
  =positions= and =directions= hold =nSystems * 3 * nAtoms= doubles, =boxes=
  holds =nSystems * 9=, and =order= is the highest order wanted.
  =jet_out= holds =order * nSystems * 3 * nAtoms= doubles laid out
  =[order][system][3 * nAtoms]= and must not overlap =directions=, the geometry
  buffers or =report=.
  =report= may be NULL.
- Units :: positions, boxes and directions in Angstrom; every block of =jet_out=
  is eV/Angstrom, a force, because the Angstrom of the line parameter is
  absorbed by the direction.
- Outputs :: =RGPOT_ENGINE_OK= and, in block =k - 1= of system =s=, the exact
  =k=-th derivative with respect to =t= of the energy gradient at
  =positions_s + t * directions_s=, at =t = 0=.
  These are derivatives, not Taylor coefficients, and not the interval
  enclosures of the energy jet of =rgpot_jet_*=.
  Block 0 is the Hessian-vector product, so an engine that serves the jet also
  serves what =rgpot_engine_hvp= returns, and for the same inputs the two agree
  in every bit when the backend takes both from one evaluation.
  =report= receives =RgpotEngineDerivativeReport= for the whole call: when
  =tracked= is nonzero, =operations= times the machine epsilon times =scale= is
  the engine's first-order estimate (not a rigorous bound) of the roundoff of
  the returned derivatives, with =operations= summed and =scale= the largest
  over the systems; when =tracked= is 0 the other fields are 0.
- Errors :: returns
  =RGPOT_ENGINE_ERR_INVALID= for a NULL pointer, an invalid system or atom count, =order= below 1 or overlapping buffers; =RGPOT_ENGINE_ERR_UNSUPPORTED=
  when the backend has no gradient jet or =order= exceeds
  =jet_order=; and =RGPOT_ENGINE_ERR_EVAL= when the implementation throws.
  The reason is available from =rgpot_engine_last_error=.
  Nothing is written to =jet_out= or =report= on an error.

Optional symbol, minor 11.
A backend serves it by deriving =rgpot::GradientJet= next to its potential
class; the table finds the interface with =dynamic_cast=, so =PotentialBase= and
its layout stamp do not change.
Absence of the symbol, =jet_order= 0 or an order above =jet_order= is a hard
unsupported result; the adapter and the Rust loader never approximate it with
finite differences.
A host loads an engine of an earlier minor that has neither the symbol nor the
trailing caps field, and gets that unsupported result only when it asks for the
jet.

** Charge and spin

=rgpot_engine_set_charge_spin= sets the total charge and the spin of the next
calls on a handle, and a negative spin returns 1.
A value the backend or task cannot take returns 3, keeps the values in force and
leaves the reason in =rgpot_engine_last_error=.
No engine returns 0 for a value its model does not receive.

| library | charge and spin |
|---------+-----------------|
| =libuma_engine= | graph inputs of every call; =UmaParams.charge= and =spin= at create |
| =libmetatomic_engine= | system data the model declares; =MetatomicParams.charge= and =spin= at create |
| =libskala_engine= | the NWChem input of the next call; =NWChemParams.charge= and =multiplicity= at create |
| =libclassical_engine=, =libmopac_engine=, =libnwchem_engine=, =libxtb_engine= | none, so 3 for any value |

A UMA package records the charge and spin it was exported for, and the next
force call reports a mismatch.
A Metatomic model reads the charge as =rgpot::charge= and the multiplicity as
=rgpot::spin_multiplicity= or =rgpot::spin=.
Each system carries the names the model declares in =requested_inputs=.
Without =attachSystemExtras=, a model that declares none of them gets 3 from
=rgpot_engine_set_charge_spin=.
A value the model does not read must stay at its default, charge 0 or
multiplicity 1.
=rgpot_engine_set_charge_spin= returns 3 for another, and =create= fails for one
in =MetatomicParams=.
=MetatomicParams.attachSystemExtras= attaches all three names and accepts any
value, for a model that reads them without declaring them.
It needs =checkConsistency= off, because metatomic then rejects data the model
does not declare.
[[file:../howto/engine-metatomic.org][Metatomic and the engine ABI]] shows the
declaration.

** UMA unpack cache

=UmaParams.cacheDir= (=UmaConfig::cache_dir= for a directly compiled =UmaPot=)
names the root of the persistent cache that the =.pt2= is unpacked into.
When it is empty the root is =$RGPOT_CACHE_DIR=, then =$XDG_CACHE_HOME/rgpot=
(absolute values only), then =.rgpot-cache= in the working directory. torch's
=AOTIModelPackageLoader= is not used, because it unpacks into a new directory
under the system temporary directory and leaves it behind when the process dies.

| Path under the root                         | Contents                                             |
|---------------------------------------------+------------------------------------------------------|
| =aoti/<sha256>.model/=                      | the package's =data/aotinductor/model= files and constants, as torch lays them out |
| =aoti/<sha256>.model/rgpot-unpack.manifest= | package digest, model name, and the size of every unpacked file |
| =aoti/.<sha256>.model.tmp-*=                | an unpack in progress                                |

=<sha256>= is the digest of the =.pt2= bytes, so two models never share a
directory and a rewritten package gets a new one.
An unpack is written into a private =.tmp-= sibling and renamed into place once
its manifest is complete.
Processes and threads that load the same package at once each build a sibling,
one rename wins, and the others use the winner's directory.
A directory whose manifest is missing or whose files have the wrong size is
replaced.
Shared libraries lose the executable-stack flag (=PT_GNU_STACK= =PF_X=) on the
way, for loaders that refuse an executable stack.
A =.tmp-= sibling older than an hour, left by a process that died, is removed
the next time that package is loaded.

** UMA checkpoint provenance

=rgpot_engine_model_digest= of =libuma_engine= is the SHA-256 of the =.pt2=.
The digest of the weights inside it is package metadata, written by
=scripts/export_uma_aoti.py=:

| Key                      | Value                                                          |
|--------------------------+----------------------------------------------------------------|
| =checkpoint_source=      | =cli=, =env= or =hf=: where the exporter took the checkpoint from |
| =checkpoint_path=        | the local checkpoint file (=cli= and =env=)                    |
| =checkpoint_hf_repo=     | Hugging Face repository (=hf=)                                 |
| =checkpoint_hf_filename= | file inside that repository (=hf=)                             |
| =checkpoint_hf_revision= | commit the file was served from (=hf=)                         |
| =checkpoint_sha256=      | SHA-256 of the checkpoint file, 64 lowercase hexadecimal digits |

=UmaPot::checkpointProvenance()= returns them as a =UmaCheckpointProvenance=,
whose fields are =std::optional= and unset for packages exported before the keys
existed.
=UmaPot= prints =checkpoint_sha256= on stderr when it loads the package, and
=unset= for those packages.
No engine ABI call returns the keys.
A malformed =checkpoint_sha256=, =checkpoint_hf_revision= or =checkpoint_source=
fails the load.

** CP2K shim

=CP2KPot= drives CP2K through
=libcp2kc_rgpot=, a shim over libcp2k declared in =CppCore/rgpot/CP2KPot/cp2kc_abi.h=
(=CP2KC_ABI_VERSION= 1).
This is a separate ABI from the engine table.
The shim is the only target that links libcp2k and MPI; =CP2KPot= opens it with
=dlopen=, so =librgpot= gains neither dependency.
Meson builds it with
=-Dwith_cp2k=enabled= from the =libcp2k= pkg-config module (CMake: =-DRGPOT_WITH_CP2K=ON=).
Without it =librgpot= contains no CP2K code, =potserv CP2K= exits with an error
naming the option, and the other potserv backends refuse the =cp2k= arm in
=configure()=.
=CP2KPot= tries =CP2KParams.enginePath=, then
=CP2KC_LIBRARY=, then =RGPOT_CP2K_ENGINE=, then =libcp2kc_rgpot.so= and
=./libcp2kc_rgpot.so= (=.dylib= on macOS).

| symbol | purpose |
|--------+---------|
| =cp2kc_abi_version=, =cp2kc_version=, =cp2kc_available= | identity |
| =cp2kc_adopt_calculator_comm= | borrow the calculator's =MPI_Comm= |
| =cp2kc_session_create= | write the deck to =dir/input.inp=, initialise libcp2k once |
| =cp2kc_session_select_orbitals= | name the key whose force environment the next call uses |
| =cp2kc_session_calculate= | positions and cell in Bohr in, Hartree and Hartree/Bohr forces out |
| =cp2kc_session_destroy= | destroy the session's force environments |

The shim uses CP2K's atomic units and takes no Cap'n Proto.
=CP2KPot= renders the deck from =CP2KParams= and the first geometry, multiplies
positions and cell rows by =ANGSTROM_TO_BOHR=, and returns the energy times
=HARTREE_TO_EV= and the forces times =HARTREE_BOHR_TO_EV_ANGSTROM=. libcp2k
returns forces, so there is no sign change.
The cell rows are the cell vectors a, b and c.

=cp2kc_session_calculate= returns 0 on success, 1 for a bad argument (including
an atom count that differs from the deck), 2 when the SCF did not converge, and
a negative value on a fatal error.
The rendered deck sets =IGNORE_CONVERGENCE_FAILURE=, so CP2K warns instead of
calling =MPI_ABORT=.
After each evaluation the first rank of the calculator reads the new part of
=cp2k.out= for =SCF run NOT converged= and shares the result, so every rank
returns 2 for the same call.
=CP2KPot= turns code 2 into =rgpot::CP2KScfError= (a =std::runtime_error=) on
every rank without the error exchange.
Any other failure takes the abort path described in [[file:mpi.org][MPI]].
=CP2KPot= sets =has_stress= to 0.

** Rust loader (=rgpot-core= =engine= feature)

=rgpot_core::engine=, a thin Rust wrapper over the symbols declared in =CppCore/rgpot/engine_c_abi.h=.

*** Plugin lifetime

Engine plugins stay resident.
The loader keeps one process-wide registry entry per plugin file, keyed by the
device and inode of the canonical path.
An entry holds the =dlopen= handle and the resolved =EngineSymbols=.
A later load of the same file through any path, symlink or hard link reuses the
entry and does not call =dlopen= again.
The library is opened with =RTLD_NODELETE=, and the loader never calls =dlclose=
on it.
Dropping an =EnginePotential=, or the =PotentialImpl= built from it, calls
=rgpot_engine_destroy= and leaves the library mapped.

A backend may keep OpenMP or CUDA runtimes, Torch thread pools, MPI state,
GROMACS, LAMMPS or OpenMM state, TLS destructors or =atexit= handlers that call
into the library after its last instance is gone.
Unmapping such a library crashes the process later, or at exit.
A load that fails its required-symbol check, its ABI check or
=rgpot_engine_create= does not stay resident.
The loader destroys any engine the attempt created, closes the handle, and keeps
no registry entry for the file.
A later load of the same file opens it again, runs its static constructors
again, and returns the same error.
A library linked with =-z nodelete= stays mapped after that close, as it does
after any =dlclose=.

Two loads are refused with =EngineError::Load=:

- A path whose file was replaced after it was loaded :: The path names a new
  inode, but the dynamic linker would return the mapping of the old one.
  A file replaced while its first load runs is refused the same way, and the
  handle of that attempt is closed.
  Load the new file from another path, or restart the process.
- A bare library name such as =libuma_engine.so= :: The dynamic loader resolves
  it through its search path rather than the filesystem, so the file cannot be
  identified before it is opened.
  Pass a path that names the file.

A plugin can opt out of residency.
When it exports
=rgpot_engine_unload_policy= returning =RGPOT_ENGINE_UNLOAD_SAFE= and its stamp
reports minor 7 or later, the loader opens it without =RTLD_NODELETE=.
It still stays loaded until the =unsafe= =EnginePotential::unload(path)= removes
its registry entry and calls =dlclose=.
=unload= returns =EngineError::Unsupported= for =rgpot_engine_unload_policy=
when the plugin has not opted in, and =EngineError::Invalid= while an
=EnginePotential= or a =PotentialImpl= built from it is alive or when the file
was never loaded.
=unload= releases the registry lock before it calls =dlclose=, so a destructor
of the plugin may load another engine.
A later =load= opens the file again.

=libuma_engine=, =libmetatomic_engine=, =libxtb_engine=, =libopenmm_engine=,
=libnwchem_engine= and =libskala_engine= are also linked with =-z nodelete=, so
a host that does call =dlclose= on them leaves them mapped.

  (=code=, =message=), and =Lock= (=operation=, =message=).
- =EngineRequest= :: Single-geometry input with =positions= (Angstrom, row-major
  =[n_atoms, 3]=), =atomic_numbers=, and =box_matrix= (row-major 3x3 lattice in
  Angstrom).
- =EngineEvaluation= :: Output containing =energy= (eV) and =forces=
  (eV/Angstrom, row-major =[n_atoms, 3]=).
- =EnginePotential::load(path, config)= /
  =EnginePotential::from_symbols(symbols, config)= :: =load= takes the resident
  registry entry for =path=, opening the file on first use.
  Both verify
  =rgpot_engine_abi_version() == ENGINE_ABI_VERSION=, resolve the optional =rgpot_engine_abi_stamp=
  (treating an engine without it as minor 0, layout 1) and require
  =stamp.serves(RgpotEngineAbiStamp::HOST)=, copy =config= into an
  8-byte-aligned =Vec<u64>= buffer (so engines that cast =config= to
  =capnp::word= never receive an unaligned pointer), check
  =rgpot_engine_available() != 0= when the engine exports it, and call
  =rgpot_engine_create=.
  =EnginePotential::abi_stamp()= returns the resolved stamp.
  When the engine exports =rgpot_engine_caps=, one call at creation reads
  =reentrancy=.
  A negative code (=EngineError::Lock= for =RGPOT_ENGINE_ERR_LOCK=,
  =EngineError::Fatal= otherwise) rejects the engine: the loader destroys the
  new handle once and returns the error.
  A positive code or a truncated answer is not trusted, so the engine is
  serialized process wide like =reentrancy= 2.
  Only a successful answer of 0 or 1 skips that lock.
- =EnginePotential::force(&request)= and
  =EnginePotential::force_batch(&atomic_numbers, &positions, &boxes)= ::
  Validates input lengths and output finiteness, dispatches to
  =rgpot_engine_force= or
  =rgpot_engine_force_batch=, and maps positive codes to =EngineError::Recoverable= and negative codes to =EngineError::Fatal= using =rgpot_engine_last_error=
  when present.
  A negative status, including
  =RGPOT_ENGINE_ERR_LOCK= (=EngineError::Lock=), poisons the handle: every later call on that =EnginePotential= (or the =PotentialImpl= built from it) returns the same error without calling into native code, while dropping the handle still calls =rgpot_engine_destroy=
  once to release the =RgpotEnginePot= allocation.
  The process-wide lock of a =reentrancy= 2 engine is poisoned when a thread
  panics inside native code that holds it.
  The first call that finds it poisoned returns =EngineError::Lock= and poisons
  its handle the same way, without calling into native code.
- =EngineSession= :: Owns the callbacks of one =EnginePotential=.
  It borrows a =CoordinateTransform= only for the duration of each =force= or
  =force_batch= call and never keeps it.
  A callback or transform failure during a call is considered before the code
  the engine returns.
  A fatal failure from either side wins over a recoverable one.
  The first fatal failure poisons the handle, and every later call returns that
  =EngineError::Fatal= with the same code and message.
  A failure reported without a message carries one that names its code.
- =EngineSession::set_callbacks(callbacks)= :: Registers owned callbacks, or clears them with =None=, which passes a NULL table to =rgpot_engine_set_callbacks=.
  On success the session installs the new callbacks first and then drops the old
  ones, so the engine never holds a context the session has freed.
  A panic in the old callbacks' destructor is caught and reported as a fatal
  failure, which poisons the session; it never unwinds out of the call.
  On a nonzero return the previous callbacks stay registered and the refused
  ones are kept alive until the engine is destroyed, because an engine built
  before the header forbade it may have retained them.
  Dropping the session destroys the engine before it frees any callbacks.
- =EngineSession::attach_cache(path)=, =EngineSession::cache_counts()= and
  =EngineSession::clear_cache()= :: Attach a result cache, read its counts, and detach it through =rgpot_engine_set_cache=
  and =rgpot_engine_cache_counts=.
  =cache_counts()= returns =(computed, served)= and reports
  =EngineError::Unsupported= when no cache is attached or the plugin lacks the
  symbols.
  =clear_cache()= detaches the cache and leaves its entries on disk.
  Each call goes through the same fatal-failure handling as a force call.
- =EngineSession::model_state()= and =EngineSession::hint(message)= :: Read =rgpot_engine_model_state=
  (zero when the engine lacks it) and send a typed hint through
  =rgpot_engine_hint=.
  The message of a failed hint is the one the engine wrote to the error buffer,
  or one naming the code when it wrote none.
- =EnginePotential::caps()= / =EnginePotential::hvp(&request, direction)= ::
  Reads the size-prefixed engine capability structure and dispatches the exact
  product.
  A missing symbol, a false
  =analytic_hvp= bit, or =RGPOT_ENGINE_ERR_UNSUPPORTED= returns
  =EngineError::Unsupported= (retaining the engine's last-error message) without
  a finite-difference fallback.
- =EnginePotential::taylor_jet(&JetBatchRequest, order)= :: Dispatches =rgpot_engine_taylor_jet=
  for a uniform batch in one engine call and returns a =GradientJet=: =order()=,
  =n_systems()=, =derivative(k)= (every system, =k= in =1..=order=; block 0 is the Hessian-vector product), =system_derivative(k, s)=
  and =report()=, a =DerivativeReport= (=operations= summed, =scale= the
  largest) or =None= when the engine does not count operations.
  =JetBatchRequest= holds =atomic_numbers=, =positions=, =directions= and
  =boxes=.
  A missing symbol, a
  =jet_order= below =order=, or =RGPOT_ENGINE_ERR_UNSUPPORTED= returns
  =EngineError::Unsupported= naming =rgpot_engine_taylor_jet= (retaining the
  engine's last-error message) without a finite-difference fallback.
  =order= 0, a length mismatch and a non-finite position, direction or box are
  =EngineError::Invalid= before the engine is called.
  A non-finite or negative report scale is =EngineError::Invalid=, and the
  loader substitutes no other scale.
  =EngineSession::taylor_jet(&JetBatchRequest, order)= is the same call on a
  session: a failure a registered callback reports during the call is settled
  with the engine's return code as for =EngineSession::force=, so a fatal one
  poisons the session.
  =EnginePotential::caps()= asks the engine once and caches the answer;
  =EngineCaps::jet_order= carries the capability and is 0 for an engine whose
  caps struct ends before the field.
- =EnginePotential::into_potential(self)= :: Converts the instance into a =PotentialImpl= callback handle, serializes calls to its engine instance, and registers an analytic callback on the underlying =rgpot_potential_t= only when both =rgpot_engine_caps= and =rgpot_engine_hvp= are exported and =analytic_hvp=
  is true.
- =unsafe EnginePotential::unload(path)= :: Removes the registry entry of a
  plugin that declared itself unload-safe and calls =dlclose=, as described
  under the plugin lifetime above.
  The caller vouches for the declaration: no thread, TLS destructor, =atexit=
  handler or callback of the library may run afterwards, and no function pointer
  taken from it may be called.
