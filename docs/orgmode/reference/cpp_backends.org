* C++ engine-backed potentials

These potentials call an external program or library: a quantum-chemistry
engine, a tight-binding library, a machine-learned model or a socket peer.
Every class derives from =rgpot::Potential<Derived>=, except the dlopen
frontends =XTBDlopen= and =MetatomicDlopen=, which have no base class and
declare =forceImpl= themselves.
The members they inherit (=forceImpl=, =forceBatch=, =caps=, the call operator)
are described with the base class; this page lists only the members each class
declares itself.
The in-process kernels are in [[file:cpp_potentials.org][C++ potentials]].

Unless an entry says otherwise, a class takes positions and the cell in Angstrom
(cell vectors as rows) and returns the energy in eV and the forces in
eV/Angstrom. Engines that work in atomic units get positions converted with =units::ANGSTROM_TO_BOHR=, the energy with =units::HARTREE_TO_EV= and gradients with =units::NEG_GRAD_TO_FORCE= (minus Hartree/bohr
to eV/Angstrom), all from =CppCore/rgpot/units.hpp=.

** How each class finds its engine

The dlopen frontends try a list of library names in order.
A bare name is resolved by the dynamic linker search path.
=CP2KPot=, =CPMDPot=, =MOPACPot=, =NWChemPot=, =XTBDlopen= and =MetatomicDlopen=
stop at the first library that opens and then check its symbols, so a library
with missing symbols ends the search.
=LammpsPot=, =GromacsPot= and =OpenMMPot= skip a library that lacks the symbols
and try the next name.

| Class        | Library                 | Search order                                                                                  |
|--------------+-------------------------+-----------------------------------------------------------------------------------------------|
| =CP2KPot=    | =libcp2kc_rgpot=        | =enginePath=, =CP2KC_LIBRARY=, =RGPOT_CP2K_ENGINE=, =libcp2kc_rgpot.so=, =./libcp2kc_rgpot.so= |
| =CPMDPot=    | =libcpmdc=              | =enginePath=, =CPMDC_LIBRARY=, =RGPOT_CPMDC_ENGINE=, =RGPOT_CPMD_ENGINE=, =libcpmdc.so=, =./libcpmdc.so= |
| =MOPACPot=   | =libmopacc=             | =Config::engine_path=, =MOPACC_LIBRARY=, =RGPOT_MOPACC_ENGINE=, =libmopacc.so=, =./libmopacc.so= |
| =NWChemPot=  | =libnwchemc=            | =enginePath= alone when set; else the variables that are set among =NWCHEMC_LIBRARY=, =RGPOT_NWCHEMC_ENGINE= and =RGPOT_NWCHEM_ENGINE=, in that order, with no default names after them; else =libnwchemc.so=, =./libnwchemc.so= |
| =SkalaPot=   | =libnwchemc=            | as =NWChemPot=                                                                                |
| =LammpsPot=  | engine plugin           | =engine_path= alone when set; else =RGPOT_LAMMPS_ENGINE=, =LAMMPS_ENGINE=, =liblammps_engine.so=, =liblj_engine.so= |
| =GromacsPot= | =rgpot_md_native_force= | =engine_path= alone; empty means the in-process Lennard-Jones                                 |
| =OpenMMPot=  | =rgpot_md_native_force= | as =GromacsPot=                                                                               |
| =XTBDlopen=  | =libxtb_engine=         | =engine_path= alone when set; else =RGPOT_XTB_ENGINE=, =XTB_ENGINE=, =libxtb_engine.so=, then each directory of =EON_POTENTIALS_PATH= and =RGPOT_ENGINE_PATH= |
| =MetatomicDlopen= | =libmetatomic_engine= | =engine_path=, =RGPOT_METATOMIC_ENGINE=, =METATOMIC_ENGINE=, =libmetatomic_engine.so=, then each directory of =EON_POTENTIALS_PATH= and =RGPOT_ENGINE_PATH= |

After the =.so= names the CP2K, CPMD, MOPAC and NWChem lists also try the
=.dylib= names (bare and with =./=), and CPMD, MOPAC and NWChem try =cpmdc.dll=,
=mopacc.dll= and =nwchemc.dll=.
=LammpsPot= uses =.dylib= names on macOS and =.dll= names on Windows instead of
=.so=.
=XTBDlopen= and =MetatomicDlopen= try the =.dylib= name before the =.so= name on
macOS, and on Windows try =xtb_engine.dll= and =libxtb_engine.dll=
(=metatomic_engine.dll= and =libmetatomic_engine.dll=) in place of the =.so=
name.
=TBLitePot= and =XTBPot= link =libtblite= and =libxtb= at build time.
=MetatomicPot= and =UmaPot= link libtorch.
=XTBDlopen= and =MetatomicDlopen= are in every =librgpot= and need neither;
their engine libraries carry the C ABIs in
[[file:engine_abi.org][Engine C ABI]].
=IPIPot= opens a socket and waits for a driver.
=ORCAPot= starts the =orca= program for every force and needs no library.

None of the dlopen constructors throw when the library is missing.
They record the reason, =available()= returns false, and the first force throws
=std::runtime_error= with that reason.
The exceptions are =LammpsPot=, =GromacsPot= and =OpenMMPot= with an
=engine_path=: their constructors throw =std::runtime_error= when no library
opens.
=XTBDlopen= and =MetatomicDlopen= also throw from the constructor, so
=available()= is true for every object they construct.

** CP2K

The Quickstep method is VandeVondele and coauthors, Computer Physics
Communications 167, 103-128 (2005), doi:10.1016/j.cpc.2004.12.014.
CP2KPotFakeEngineTest does not run Quickstep.
Its surface is a spring, half k times the sum of squared displacements, in
Hartree and Bohr with k = 0.5.
On the water geometry in that test the spring is 1.8600113677425840 Hartree, so
the host energy is 50.613487749571874 eV, and the test requires a relative
agreement of 1e-12.

*** =rgpot::CP2KPot=

#+attr_rgpot: signature
#+begin_src cpp
CP2KPot();
explicit CP2KPot(const ::CP2KParams::Reader &params);
#+end_src

- Inputs :: optional =CP2KParams= (Cap'n Proto); the default constructor uses
  the schema defaults.
- Units :: positions and cell in Angstrom, energy in eV, forces in
  eV/Angstrom. The class converts positions and cell to bohr, and the shim's Hartree energy and Hartree/bohr
  forces back.
  The shim returns forces, so there is no sign change.
- Outputs :: a potential that runs CP2K Quickstep through the =libcp2kc_rgpot=
  shim.
- Errors :: the constructors do not throw when the shim is missing; see
  =loadError=.
  A force throws =rgpot::CP2KScfError= (a =std::runtime_error=) when the SCF
  does not converge, on every rank of the calculator.
  Any other failure throws =std::runtime_error=: shim not loaded, a bad
  =inputTemplate=, =nAtoms= of zero, a null buffer, a refused calculator
  binding, the shim refusing the deck or the orbital key, or a nonzero shim
  status.

The shim must report =cp2kc_abi_version()= equal to =CP2KC_ABI_VERSION= and
export the session functions, and =cp2kc_available()=, when exported, must be
nonzero.
The deck is rendered from the params (or from =inputTemplate=, which must
contain both =@RGPOT_COORD@= and =@RGPOT_CELL@=) on the first force and again
whenever the sequence of atomic numbers changes.
A non-empty =dataDir= sets =CP2K_DATA_DIR= before the session starts.
The build option is =-Dwith_cp2k=enabled= and it needs =-Dwith_rpc=true=.

*** =rgpot::CP2KPot::setParams=

#+attr_rgpot: signature
#+begin_src cpp
bool setParams(const ::CP2KParams::Reader &params);
#+end_src

- Inputs :: =params=, the next =CP2KParams=.
- Units :: as the message fields (=cutoffRy= in Rydberg); the call converts
  nothing.
- Outputs :: true when the shim is loaded and the params are usable.
  False when the shim cannot be loaded, or =inputTemplate= lacks
  =@RGPOT_COORD@= or =@RGPOT_CELL@=.
  The params are stored either way.
- Errors :: no exception of its own; failures are reported by the return value
  and =loadError=.

The live session is destroyed when the serialized params differ or =enginePath=
changes; otherwise it keeps its wavefunctions.
The shim is loaded again when it was not loaded or =enginePath= changed.

** CPMD

The method is Car and Parrinello, Phys.
Rev. Lett. 55, 2471 (1985), doi:10.1103/PhysRevLett.55.2471.
=CPMDPot= loads =libcpmdc= and does not carry a plane-wave energy of its own.
Positions are Angstrom and the energy is eV.
The parameters are the =CPMDParams= arm.
The tutorial's 0.77 eV is the stand-in engine on a 20 Angstrom cell (0.75 plus
0.001 times the cell's z length), not a published water energy.

*** =rgpot::CPMDPot=

#+attr_rgpot: signature
#+begin_src cpp
CPMDPot();
explicit CPMDPot(const ::CPMDParams::Reader &params);
#+end_src

- Inputs :: optional =CPMDParams= (Cap'n Proto); the default constructor uses
  the schema defaults.
- Units :: positions in Angstrom, energy in eV, forces in
  eV/Angstrom, stress in eV/Angstrom^3.
  With the session ABI, rgpot sends a =ForceInput= tagged =angstrom= and =eV=
  and the engine returns those units.
  With the one-shot ABI, positions go in Angstrom and the class converts the
  Hartree energy and the
  Hartree/bohr gradient. It also converts a Hartree/bohr^3 stress when the
  engine exports =cpmdc_last_stress= and reports a valid tensor.
- Outputs :: a potential that runs CPMD through =libcpmdc=.
- Errors :: the constructors do not throw when the engine is missing.
  A force throws =std::runtime_error= when the engine is not available, =nAtoms=
  is zero, a buffer is null, the calculator binding was refused, the orbital key
  is refused, the engine reports failure, or the returned =PotentialResult= is
  malformed or has the wrong force count.

The engine must export the feature discovery functions (=cpmdc_feature_count=,
=cpmdc_feature_table=, =cpmdc_feature_find=) and either the session result ABI
or =cpmdc_energy_gradient= with =cpmdc_set_params=.
A non-empty =cpmdRoot= sets =CPMD_ROOT=.
The one-shot ABI does not receive the cell.
The class is built when =-Dwith_rpc=true=.

*** =rgpot::CPMDPot::setParams=

#+attr_rgpot: signature
#+begin_src cpp
bool setParams(const ::CPMDParams::Reader &params);
#+end_src

- Inputs :: =params=, the next =CPMDParams=.
- Units :: as the message fields (=cutOffRy= in Rydberg); the call converts

- Outputs :: true when the engine is loaded and accepts the params (a session is
  created, or =cpmdc_set_params= returns 0).
- Errors :: no exception of its own; a false return covers a missing engine and
  a refusal.

The engine is loaded again when it was not loaded or =enginePath= changed.
A live session is kept when the engine path and the serialized params are
unchanged.
A refused orbital key drops the session just created, so the same params are
applied again on the next call.

** MOPAC

The default model is AM1: Dewar, Zoebisch, Healy and Stewart, Journal of the
American Chemical Society 107, 3902-3909 (1985),
doi:10.1021/ja00299a024. PM6 is Stewart, Journal of Molecular Modeling 13, 1173-1213 (2007), doi:10.1007/s00894-007-0233-4.
MOPACPotTest does not pin an AM1 energy.
The fake engine returns 0.25 Hartree, and the test requires the host energy to
equal that times =HARTREE_TO_EV= (27.211386245988), which is 6.802846561497 eV.

*** =rgpot::MOPACPot=

#+attr_rgpot: signature
#+begin_src cpp
MOPACPot();
explicit MOPACPot(const Config &cfg);
#+end_src

- Inputs :: =Config= with =charge=, =spin=, =model= (0 PM7, 1 PM6-D3H4, 2
  PM6-ORG, 3 PM6, 4 AM1, 5 RM1; default 4), =tolerance=,
  =max_time= and =engine_path=.
- Units :: positions in Angstrom, energy in eV, forces in
  eV/Angstrom. =libmopacc= returns Hartree and a Hartree/bohr gradient, which
  the class converts.
  The cell is not sent; the class reports =periodic = false=.
- Outputs :: a potential that runs OpenMOPAC through =libmopacc=.
- Errors :: the constructors do not throw when the engine is missing.
  A force throws =std::runtime_error= when the engine is not loaded, =nAtoms= is
  zero, a buffer is null, or the engine reports failure.

The library must export =mopacc_energy_gradient=,
=mopacc_c_abi_version=, =mopacc_abi_version=, =mopacc_result_size= and =mopacc_params_size=.
Both versions must equal 2 (=RGPOT_MOPACC_C_ABI_VERSION= and
=MOPACC_ABI_VERSION=), =mopacc_result_size= must equal =sizeof(MopacCResult)=,
and =mopacc_params_size= must equal =sizeof(MopacCParams)=.
A later ABI may change the layout without changing the sizes, so a library
reporting version 3 is refused even when its sizes match.
These checks run before any call that returns a =MopacCResult=; a library that
fails one stays unloaded, and the load error names the missing symbol or the
expected and found values.
When the library exports =mopacc_available=, that must be nonzero.
The constructor passes the params once through =mopacc_set_params= when present;
a nonzero status leaves the engine unloaded.

*** =rgpot::MOPACPot::available=

#+end_src

- Inputs :: none.
- Units :: none.
- Outputs :: true when =libmopacc= passed the load check above and
  =mopacc_set_params=, when exported, returned 0.
- Errors :: none.

** NWChem

The engine is NWChem: Valiev and coauthors, Computer Physics Communications 181,
1477-1489 (2010),
doi:10.1016/j.cpc.2010.04.018, and Aprà and coauthors, Journal of Chemical Physics 152, 184102 (2020), doi:10.1063/5.0004997.
NWChemPotTest requires a water B3LYP/6-31G* energy below -2070.0 eV and a second
SCF within 1e-3 eV of the first.

#+attr_rgpot: compile requires=has_rpc
#+begin_src cpp
#include "rgpot/NWChemPot/NWChemPot.hpp"

#include <capnp/message.h>

#include <cstdio>
#include <string>

int main() {
  ::capnp::MallocMessageBuilder msg;
  auto params = msg.initRoot<::NWChemParams>();
  params.setTheory("scf");
  params.setBasis("6-31g*");
  params.setCharge(0);
  params.setMultiplicity(1);

  rgpot::NWChemPot pot(params.asReader());
  std::string message;
  ::capnp::MallocMessageBuilder cfg_msg;
  auto cfg = cfg_msg.initRoot<::PotentialConfig>();
  cfg.setNwchem(params.asReader());
  if (!pot.setPotentialConfig(cfg.asReader(), &message)) {
    std::fprintf(stderr, "%s\n", message.c_str());
    return 1;
  }
  return 0;
}
#+end_src

** ORCA

=ORCAPot= runs the =orca= executable as a child process and reads the energy and
gradient from the =.engrad= file it writes.
ORCA is not linked or loaded.
It is described in Neese, WIREs Computational Molecular Science 2, 73-78 (2012),
doi:10.1002/wcms.81, and in Neese, Wennmohs, Becker and Riplinger, J. Chem. Phys. 152, 224108 (2020), doi:10.1063/5.0004608.
Version 5 is Neese, WIREs Computational Molecular Science 12, e1606 (2022),
doi:10.1002/wcms.1606, and version 6 is Neese, WIREs Computational Molecular Science 15, e70019 (2025), doi:10.1002/wcms.70019.
The how-to is [[file:../howto/orca.org][ORCA single points]].
The tests use a fake =orca= script that returns a Hartree energy of -1.25 and a
gradient of 0.01 Hartree/bohr times the component number, and require the host
energy and forces to equal those times the =units.hpp= factors.
They do not pin an ORCA energy.

*** =rgpot::ORCAConfig=

- Inputs :: =executable= (a path, or a bare name looked up on PATH; empty looks
  up =orca=), =method= (an ORCA method keyword, required), =basis= (a basis set
  keyword, empty for a composite method), =keywords= (further simple-input
  keywords, empty for none), =charge= (default 0), =multiplicity= (default 1),
  =nprocs= (default 1),
  =maxcore_mb= (default 1024), =restart= (default true), =scratch_dir= (empty
  for the system temporary directory),
  =keep_files= (default false) and =timeout_s= (default
  =ORCAConfig::kDefaultTimeout=, 3600 seconds; 0 waits with no limit).
- Units ::
  =maxcore_mb= in MB per process; =charge= in elementary charges; =timeout_s= in
  seconds; the other fields have no unit.
- Outputs :: a plain struct read by =rgpot::ORCAPot=.
  =method=, =basis= and =keywords= become the =!= line, =nprocs= above 1 becomes
  =%pal nprocs=, =maxcore_mb= becomes =%maxcore=, and =charge= and
  =multiplicity= go on the =* xyz= line.
  =restart= turns the =%moinp= and =MORead= reuse of the previous =.gbw= on and
  off.
  =timeout_s= is the time to wait for the =orca= process.
  The process is the leader of a new process group.
  Past the limit that group is sent SIGTERM and, if any process in the group is
  still alive two seconds later, SIGKILL even if the leader has exited, and the
  child is reaped.
- Errors :: =rgpot::ORCAPot= throws
  =std::invalid_argument= for an empty =method=, for =multiplicity=, =nprocs= or =maxcore_mb=
  below 1, for a =timeout_s= that is negative or not finite, and for a =method=,
  =basis= or =keywords= that holds a line break.

*** =rgpot::ORCAPot=

#+attr_rgpot: signature
#+begin_src cpp
explicit ORCAPot(const ORCAConfig &config);
#+end_src

- Inputs :: =config=, an =rgpot::ORCAConfig=.
- Units :: positions in Angstrom, energy in eV, forces in
  eV/Angstrom. ORCA takes Angstrom in a =* xyz= block, so the positions are written as they are. The =.engrad= energy in Hartree is multiplied by =units::HARTREE_TO_EV= and its Hartree/bohr
  gradient by =units::NEG_GRAD_TO_FORCE=.
  The box must be absent or all zero, in Angstrom.
- Outputs :: a potential that runs one ORCA energy and gradient per force call.
  =caps()= reports =Reentrancy::PerInstance=, =periodic = false= and no stress.
  The constructor resolves the executable and makes a directory of its own under
  =scratch_dir=; the destructor removes it unless =keep_files= is set.
  Each call writes
  =rgpot_orca.inp= there, closes extra file descriptors above 2 before =exec=, runs =orca rgpot_orca.inp=
  with the standard output in
  =rgpot_orca.out= and the standard error in =rgpot_orca.err=, and reads
  =rgpot_orca.engrad= in the C locale (as when writing coordinates).
  An =.engrad= and a =.gbw= left by an earlier call are removed first, and any
  removal failure other than a missing file throws =rgpot::ORCAError=.
  The orbitals of a successful call are copied to =rgpot_orca_guess.gbw=, and
  the next call with the same atomic numbers reads them through =%moinp= and
  =! MORead=.
  A call without a =.gbw=, after a failure, after =reset()=, or with other
  atomic numbers starts from ORCA's own guess.
- Errors :: the constructor throws =std::invalid_argument= in the cases of
  =rgpot::ORCAConfig=, and =rgpot::ORCAError= when no executable is found or the
  directory cannot be made.
  A force call throws =std::invalid_argument= for a box with a non-zero entry
  (ORCA has no periodic boundary conditions), for an atomic number outside 1 to
  118, and for a charge and multiplicity that the electron count cannot hold.
  It throws =rgpot::ORCAError=, a
  =std::runtime_error=, when a stale =.engrad= or =.gbw= cannot be removed, the input cannot be written, ORCA cannot be started or is ended by a signal, the run passes =timeout_s=
  (the process group is then stopped and the child reaped), ORCA exits with a
  non-zero status, no =.engrad= appears, the =.engrad= is malformed or lists
  other atoms, or the energy or a gradient component is not finite.
  The message holds the last 2048 bytes of the standard error and of the output
  file.

** ORCA through liborcac

=ORCACPot= (=CppCore/rgpot/ORCACPot/=) is the frontend of the split orcac shim
(=liborcac=), on the pattern of =MOPACPot=: it dlopens the library and keeps one
orcac session, which owns one run directory and one set of stored orbitals.
=liborcac= writes the ORCA input, runs ORCA and reads the =.engrad=; see the
rgpot integration guide in the orcac repository.
It is in every =librgpot= and needs neither ORCA nor =liborcac= to build.
=rgpot::makePotential= builds it for the =orca= arm.
=ORCAPot= is the separate in-process frontend.

=ORCACPot= speaks C ABI 1 of =liborcac=: plain C structs (=OrcaCConfig= and
=OrcaCResult=, each with a
=struct_size=), integer status codes, and thirteen exported functions, from =orcac_config_init= to =orcac_probe_executable=.
The header it builds against,
=CppCore/rgpot/ORCACPot/orcac.h=, is a vendored copy of the public =orcac.h= of the orcac repository, pinned with its orcac commit and SHA-256 in =CppCore/rgpot/ORCACPot/orcac.h.pin=.
The =OrcacHeaderPin= test checks the copy against the pin and checks that
=subprojects/orcac.wrap= fetches the pinned commit.
=CppCore/tests/orcac_abi1_exports.txt= lists the thirteen functions.

*** =rgpot::ORCACConfig=

- Inputs :: one field for each =OrcaCConfig= field: =method= (one simple-input
  token, required), =basis= (one token; empty for a composite method),
  =keywords= (further simple-input words on one line), =blocks= (verbatim =%=
  blocks), =executable= (empty lets =liborcac= search
  =$ORCAC_ORCA=, then =PATH=), =scratch_dir= (empty uses =$TMPDIR=), =charge=,
  =multiplicity=, =nprocs=, =maxcore_mb=, =timeout_s= and =restart= (true
  selects =ORCAC_GUESS_CHAIN=, false =ORCAC_GUESS_FRESH=); =engine_path=, the
  library to open.
- Units :: =maxcore_mb= in MB per process, =timeout_s= in seconds per ORCA run
  (0 waits with no limit).
- Outputs :: a plain struct read by =rgpot::ORCACPot=.
- Errors :: none; =liborcac= checks the fields when the session is created.

The =orca= arm of =rgpot::makePotential= fills it from =ORCAParams= alone; the
shared fields of =PotentialConfig=, such as =common=, are not read. orcac takes
the method as one token, so the first word of =ORCAParams.method= is the method
and the others join =keywords= (=UKS PBE0= gives the method =UKS= and the
keyword =PBE0=, the same =!= line for ORCA).
=ORCAParams.keywords= on one line that does not start with =%= stays =keywords=,
without a leading =!=; otherwise each line that starts with =!= joins =keywords=
and the other lines are =blocks=.
=keepFiles= is refused with =std::invalid_argument=, since ABI 1 always removes
the run directory.

** xtb

The default method is GFN2-xTB: Bannwarth, Ehlert and Grimme, J. Chem.
Theory Comput. 15, 1652 (2019),
doi:10.1021/acs.jctc.8b01176. Host positions are Angstrom and the host energy is eV. =XTBConfig= holds the parameters: the method, accuracy 1, an electronic temperature of 300 K, 250 iterations, charge 0 and no unpaired electrons. A numerical GFN2 energy needs libxtb, which the default build does not link, so this tree does not pin one. GFN1-xTB is the 2017 GFN-xTB method of Grimme, Bannwarth and Shushkov, Journal of Chemical Theory and Computation 13, 1989-2009 (2017), doi:10.1021/acs.jctc.7b00118.
GFN0-xTB is Pracht, Caldeweyher, Ehlert and Grimme, ChemRxiv (2019),
doi:10.26434/chemrxiv.8326202.v1. GFN-FF is Spicher and Grimme, Angewandte Chemie International Edition 59, 15665-15673 (2020), doi:10.1002/anie.202004239.

*** =rgpot::XTBConfig=

- Inputs :: =method= (=GFNMethod::GFNFF=, =GFN0xTB=, =GFN1xTB= or =GFN2xTB=;
  default =GFN2xTB=), =accuracy= (default 1.0),
  =electronic_temperature= (default 300.0), =max_iterations= (default 250),
  =charge= (default 0.0), =uhf= (unpaired electrons, default 0),
  =warm_move= (default 1.0), =warm_min_gap= (default 1.0).
- Units ::
  =electronic_temperature= in K; =charge= in elementary charges; =warm_move= in
  Angstrom; =warm_min_gap= in eV; the other fields have no unit.
- Outputs :: a plain struct read by =XTBPot= and, inside =XTBDlopenConfig=, by
  =XTBDlopen=.
- Errors :: neither class checks the values.
  A value xtb rejects fails the force with =std::runtime_error=.

  Zero or a negative =warm_min_gap= reuses the wavefunction at any gap.

*** =rgpot::XTBPot=

#+attr_rgpot: signature
#+begin_src cpp
XTBPot();
explicit XTBPot(const XTBConfig &config);
#+end_src

- Inputs :: =config=, an =rgpot::XTBConfig=; the default constructor, where
  there is one, uses its defaults.
- Units :: positions in Angstrom, energy in eV, forces in
  eV/Angstrom, stress in eV/Angstrom^3.
  The class sends positions and cell in bohr and converts the Hartree energy,
  the Hartree/bohr gradient and the Hartree virial divided by the cell volume.
  The molecule is created non-periodic in all three directions; stress is set
  when the cell volume is positive.
- Outputs :: a potential that calls the linked libxtb C API.
- Errors :: =std::runtime_error= from the constructor when the xtb environment,
  calculator or results cannot be created.
  A force throws =rgpot::SccNotConverged=, a
  =std::runtime_error=, when the SCC does not converge and the rescue below does not help, and =std::runtime_error=
  when the handles are missing, =xtb_newMolecule= fails, another single point
  failure occurs, or the energy or gradient is not finite.
  After such a failure the handles are replaced.

A new composition rebuilds the molecule.
A force starts the SCC from the previous wavefunction when the composition is
unchanged, no atom moved further than =warmMove()=, and the HOMO-LUMO gap of
that wavefunction is at least =warmMinGap()=.
A single point started that way that does not converge, or whose gap falls below
=warmMinGap()=, is run again from xtb's own guess.
GFN-FF has no orbitals, so its gap never blocks reuse.
The first single point of a force runs at most 48 SCC iterations, or
=max_iterations= when that is smaller.
An SCC that does not converge is retried at 1000, 3000 and 5000 K (those above
the configured temperature) and then evaluated again at the configured
temperature.
The build option is =-Dwith_xtb=true=.

** Metatomic

The model container is metatomic: Bigi et al., J. Chem.
Phys. 164, 064113 (2026), doi:10.1063/5.0304911.
Positions are Angstrom and the energy is eV.
The parameters are the exported model plus =MetatomicConfig=.
Reference value: the 13-atom geometry in =MetatomicPotTest=, on
=CppCore/tests/data/lj38/lennard-jones.pt=, is 98374.87753058573 eV within 1e-2,
the pin from eOn =MetatomicTest=.

*** =rgpot::MetatomicConfig=

- Inputs :: the fields and their defaults:
  =model_path= (empty; the exported model file), =device= (empty; let metatomic pick from the model's devices), =length_unit=

** i-PI socket

The socket is the i-PI force-engine protocol of Ceriotti, More and Manolopoulos,
Computer Physics Communications 185, 1019-1026 (2014),
doi:10.1016/j.cpc.2013.10.027. i-PI 2.0 is Kapil and coauthors, Computer Physics Communications 236, 214-223 (2019), doi:10.1016/j.cpc.2018.09.020.
IPIPotTest's mock returns 0.25 Hartree.
The host energy must lie within 1e-12 of 0.25 times =HARTREE_TO_EV=, which is
6.802846561497 eV.
That is a unit conversion, not a path-integral energy.

*** =rgpot::IPIConfig=

- Inputs :: =address= (default empty), =timeout_s= (default 30.0).
  =address= is =unix:/absolute/path=, =unix:<name>= (the i-PI default path with
  prefix =ipi_=), =tcp:<host>:<port>= or =tcp:<port>= (host 127.0.0.1); port 0
  lets the kernel choose.
- Units :: =timeout_s= in seconds; it covers one whole force call, including the
  wait for the driver to connect.
- Outputs :: a plain struct read by =IPIPot=.
- Errors :: =IPIPot= throws
  =std::invalid_argument= for an address without a =unix:= or =tcp:= prefix, an empty UNIX address, a UNIX name containing =/=, a UNIX path too long for the socket address, a missing or out-of-range port, or a =timeout_s=
  that is negative or not finite.
  It throws =std::runtime_error= when the host does not resolve or the socket
  cannot be bound or listened on.

*** =rgpot::IPIPot=

#+attr_rgpot: signature
#+begin_src cpp
explicit IPIPot(const IPIConfig &config);
#+end_src

- Inputs :: =config=, an =rgpot::IPIConfig=; the default constructor, where
  there is one, uses its defaults.
- Units :: positions and cell in Angstrom, energy in eV, forces in
  eV/Angstrom, stress in eV/Angstrom^3.
  On the wire the class sends bohr (the cell with lattice vectors in columns,
  and its inverse) and converts the driver's Hartree energy,
  Hartree/bohr forces and Hartree virial; the stress is -W/V.
  =timeout_s= is in seconds and covers one whole force call, including the wait
  for the driver to connect.
- Outputs :: a potential that binds the socket at construction and evaluates
  through one i-PI driver.
- Errors ::
  =std::invalid_argument= from the constructor for a bad address, port or timeout or a UNIX path that is too long; =std::runtime_error=
  when the socket cannot be bound or listened on.
  A force throws
  =std::invalid_argument= for missing buffers, zero atoms, more atoms than the protocol limit, non-finite positions or cell, or a singular cell, and =std::runtime_error=
  on a timeout, a disconnect, an unexpected header, a driver that does not
  become READY, or a mismatched atom count.
  After a failed exchange the connection is closed and the next force waits for
  a new driver.

Atomic numbers are not sent; the driver keeps its own species list.
The destructor sends EXIT.
The force call does not write =ForceOut::stress=; read it with =copyStress=.
The build option is =-Dwith_ipi=; its default, =auto=, builds the class
everywhere except Windows.

** LAMMPS, GROMACS and OpenMM

These three classes evaluate the shifted 12-6 Lennard-Jones potential described
by =ExternalLjConfig=.
The C entry points with the same names as the three factory functions are in
=CppCore/rgpot/ExternalPot/external_potentials.h=.
The engines are Thompson and coauthors, Computer Physics Communications 271,
108171 (2022),
doi:10.1016/j.cpc.2021.108171, Abraham and coauthors, SoftwareX 1-2, 19-25 (2015), doi:10.1016/j.softx.2015.06.001,
and Eastman and coauthors, PLOS Computational Biology 13, e1005659 (2017),
doi:10.1371/journal.pcbi.1005659. The pair form is Lennard-Jones, Proceedings of the Royal Society A 106, 463 (1924), doi:10.1098/rspa.1924.0082.
No test in this tree pins an energy for these three classes.

- Inputs :: =u0= (well depth, default 1.0), =cutoff= (truncation distance,

*** =rgpot::OpenMMSession=

- Inputs :: =OpenMMSession(system, config)= with an owned
  =std::unique_ptr<OpenMM::System>= and an =OpenMMSessionConfig=.
  The session is move-only.
  =setPositions= and =setVelocities= take one =OpenMM::Vec3= per particle;
  =stepLangevin= and =runLangevin= take =kT=, =friction=, =time_step=, a plane
  point and normal and the wall points and normals, each one =OpenMM::Vec3= per
  particle, a step count and a seed, and =runLangevin= also an =OpenMMWallMode=
  and whether to record the constraint force.
- Units :: OpenMM native units: nm, nm/ps, kJ/mol,
  kJ/(mol nm), amu and ps; =kT= in kJ/mol and =friction= in ps^-1.
- Outputs :: =numParticles()= and =masses()= describe the System.
  =stepNVE= advances unconstrained Verlet dynamics with the configured or an
  explicit step.
  =stepLangevin= and =runLangevin= run the =rgpot::md::ProjectedLangevin= driver
  on the Context: projected BAOAB on the 3N hyperplane in the inverse-mass
  metric, with the System's distance constraints held in every step and planar
  walls.
  The first force of a call is evaluated on the hyperplane.
  =stepLangevin= returns the number of wall reflections and =runLangevin= an
  =OpenMMLangevinResult=; an empty plane point and normal run =runLangevin=
  without the hyperplane.
  A call with the seed of the previous call continues its stream, and setting
  positions or velocities ends it.
  =state()= returns an =OpenMMState=; =boxVectors=, =geometry=,
  =setPeriodicBox=, =usesPeriodicBoundaryConditions= and =initialize= read and
  set the cell and evaluate the forces once so a failure shows early.
- Errors :: the constructor throws =std::invalid_argument= for a null System,
  bad settings, an empty platform, a System with no particles or no massive
  particle, a negative mass, or a virtual site.
  The setters and steppers throw =std::invalid_argument= for a vector count that
  differs from the System, a non-finite entry, a negative NVE step count, or a
  wall point list and normal list of different lengths; errors of
  =rgpot::md::ProjectedLangevin= and of OpenMM pass through.
