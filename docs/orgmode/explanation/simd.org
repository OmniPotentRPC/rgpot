* SIMD paths and dispatch

LJ, Morse, the analytical EAM kernel, and the orthorhombic fold select an
instruction set at run time when the build links Google Highway.
=RGPOT_SIMD= names that target, and =rgpot::simd::chosen_target_name()= reports
the one in use.
A build without Highway keeps the scalar kernels.
Code outside a dispatched function is compiled for the compiler default,
which this repository keeps at x86-64 and armv8-a.

A product-sum uses a hardware fused multiply-add only on a target that has the
instruction.
On x86-64 the scalar kernel and the SSE2 and SSE4 kernels call a =target("fma")=
body only after =detail::fma_hw_active()= reports a usable FMA.
That bit follows glibc's hwcaps mask, so a masked FMA stays on the Dekker
product.
=target("fma")= compiles the whole body with AVX encodings, including ordinary
moves, because the fused instruction is VEX-encoded.
=rgpot/isa-allow.toml= names those functions for =avx= and =fma=:
=eam_fma=, =lj_hw=, =morse_hw=, =eam_hw=, =exact_fma_hw=,
=r2_hw=, =r2_hw_n=, =accept_row_hw=, =exp2_hw=, =exp_hw_n=, and =morse8_hw=.
The baseline caller does not contain those instructions.

The pair-list force updates and the minimum-image fold use a fixed sequence
that does not go through Highway.
=simd::detail::fma_hw_active()= reads CPUID (FMA, OSXSAVE, and AVX) and XCR0,
and on glibc 2.33 and newer it also follows the hwcaps mask.
When that probe is true, =fold_hardware= and =accumulateHw= run the hardware
instruction from =target("fma")= bodies.
Otherwise =simd::exact_fma= computes the product with a Dekker product and a
round-to-odd sum.
=RGPOT_FMA=software= selects that software path.
The hardware instruction and the software product return the same bits.

The Morse kernel computes =exp= with =simd::exp_fixed=, a fixed sequence of
IEEE additions, multiplications, and bit operations.
That sequence has no table and no fused multiply-add, so the last bit does not
depend on the C library or the instruction set.
=exp_fixed_n= and the Morse row kernel are =target_clones= for the baseline,
AVX2, and AVX-512F.
The loader picks one clone from libgcc's own CPU check, and each clone returns
the bits of the baseline one.

=target("fma")= is an x86 target name, so the fold carries it only on x86-64
under GCC or Clang, the one target where =fma_hw_active()= can be true.
On aarch64 and under MSVC the fold always runs the portable path through
=simd::mul_add=, which returns the same bits.

A compiler with contraction on may fuse a product and a sum into one fused
multiply-add, and the result can then move by an ulp.
Clang contracts by default and emits the instruction where the target has it,
which is every macOS arm64 build.
The Meson build compiles the kernels that keep fixed bits with
=-ffp-contract=off=, or =/fp:precise= under MSVC, as per-target arguments.
Meson places those after =cpp_args=, so a global =-ffp-contract=fast= does not
reach them.

A Lennard-Jones cluster whose bounding-box diagonal sits on the cutoff uses
=lj_cluster_direct= instead of the Highway kernel.
On x86-64 that walk calls =lj_avx2= only after =__builtin_cpu_supports("avx2")=.
=lj_avx2=, =eval_quad=, and =acc_quad= are =target("avx2")=, and the allowlist
names them for =avx= and =avx2=.
The same builtin's initializer, =__cpu_indicator_init=, is named for =xsave=
because it reads XCR0 with =xgetbv=.
A larger cluster stays on =simd::lj_force=.

The static gate in =ci/isa-audit= is what stops a later =-march=native=, a stray
=-mavx2=, or an intrinsic outside a dispatched function from shipping.
An instruction above the baseline is allowed only when =rgpot/isa-allow.toml=
names the function and the feature, or names the vendored file that contains a
third-party dispatcher.
On a macOS arm64 slice, ~lse~ and ~rcpc~ are baseline: they are the platform
atomics, and no other CPU can load that binary.
The gate does not execute the instruction.
A runtime test reports a path as not exercised when this machine cannot execute
it.
See =ci/isa-audit/README.org= for the allowlist format and for the reusable
workflow other repositories call by commit SHA.

A kernel added later has to keep the same bits on every path, every thread count
and every rank count, down to the sign of zero and the NaN payload class.
Reductions use a fixed width of eight partial sums in a fixed lane order, the
order of ndarray 0.17 =unrolled_dot=.
The hardware fused multiply-add and the Dekker product return the same bits.
The cluster-pair layout for such kernels is the one in Páll and Hess, Comput.
Phys.
Commun. 184, 2641 (2013),
doi:10.1016/j.cpc.2013.06.003. Per-microarchitecture builds of the surrounding stack are the EESSI model in Dröge et al., Softw. Pract. Exp. 53, 176 (2023), doi:10.1002/spe.3075.
Those runs are on real nodes, not under emulation in this CI.
