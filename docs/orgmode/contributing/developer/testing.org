* Testing

** C/C++ Tests

#+begin_src bash
meson setup bbdir -Dwith_tests=true -Dwith_rpc=true --buildtype=debug
meson compile -C bbdir
meson test -C bbdir --print-errorlogs
#+end_src

=cmake= works as well:

#+begin_src bash
cmake -B build \
  -DRGPOT_BUILD_TESTS=ON \
  -DRGPOT_BUILD_EXAMPLES=ON \
  -DRGPOT_WITH_RPC=ON
cmake --build build
ctest --test-dir build --output-on-failure
#+end_src

*** Floating-point contraction

=FastNlistTest= and =ReducedPairTest= compare kernels bit for bit with plain
products and sums.
The kernels are built with contraction off.
=CppCore/meson.build= builds those two tests the same way, so neither side fuses
and the compare stays exact.
A new test of that kind belongs in the same condition.
Outside it, the test can pass on x86-64, where the baseline has no fused
multiply-add, and miss by an ulp on macOS arm64.
To exercise contraction on x86-64, build with Clang at the default debug
buildtype.
GCC does not fuse at =-O0=, and an optimized build folds the Morse test
expressions to constants.

#+begin_src bash
CXX=clang++ meson setup bbfast -Dwith_tests=true \
  -Dcpp_args='-ffp-contract=fast -mfma'
meson compile -C bbfast
meson test -C bbfast --print-errorlogs
#+end_src

** NWChem suite (=--suite nwchem=)

Frontend + stub ABI tests always build with the main library
(=with_tests=true=).
Energy/grad tests =SKIP= unless an external =libnwchemc= is on the library path
(=NWCHEMC_LIBRARY=, =RGPOT_NWCHEMC_ENGINE=, or =RGPOT_NWCHEM_ENGINE=).
The message ABI test uses a fake =nwchemc_*= shared library and verifies rgpot
passes serialized =NWChemParams= bytes through the =dlopen= boundary.

#+begin_src bash
meson setup bbdir -Dwith_tests=true -Dwith_rpc=true
meson compile -C bbdir
meson test -C bbdir --suite nwchem --print-errorlogs
#+end_src

See
=CppCore/rgpot/NWChemPot/README.md=; the engine (=libnwchemc=) is built by the split [[https://github.com/OmniPotentRPC/nwchemc][nwchemc]]
project, not by rgpot.

** CPMD suite (=--suite cpmd=)

Frontend + stub ABI tests always build with the main library
(=with_tests=true=).
The CPMD frontend loads a split =libcpmdc= engine at runtime via
=CPMDC_LIBRARY=, =RGPOT_CPMDC_ENGINE=, or =RGPOT_CPMD_ENGINE=.
Configure-only Python smokes use =PotentialConfig.cpmd= and do not require a
live engine.

#+begin_src bash
meson setup bbdir -Dwith_tests=true -Dwith_rpc=true
meson compile -C bbdir
meson test -C bbdir --suite cpmd --print-errorlogs
pixi run -e rpctest python tests/rpc_integ.py --server-bin ./bbdir/CppCore/potserv --cpmd-smoke
#+end_src

See
=CppCore/rgpot/CPMDPot/README.md=; the engine (=libcpmdc=) is built by the split [[https://github.com/OmniPotentRPC/cpmdc][cpmdc]]
project, not by rgpot.
