* Release Process

rgpot uses a *lockstep monorepo version*: the same SemVer appears in
=meson.build=, =rgpot-core/Cargo.toml=, =towncrier.toml=, and =pixi.toml=
(workspace key only — not dependency pins such as nickel).
Git tags are =vX.Y.Z= (see =cog.toml= =tag_prefix=).

Requires [[https://docs.cocogitto.io][cocogitto]] *7+* locally and in CI (=release-prepare.yml= installs 7.0.0).
Do *not* hand-edit a =## [X.Y.Z]= section above the towncrier marker; fragments under
=docs/newsfragments/= are the only input for the next release notes block.

Tooling:

| Tool | Role |
|------+------|
| [[https://docs.cocogitto.io][cocogitto]] (=cog=) 7+ | Conventional-commit aware bump, version commit, annotated tag |
| [[https://towncrier.readthedocs.io][towncrier]] | Curated =CHANGELOG.md= from =docs/newsfragments/= |
| =scripts/release/sync-versions.sh= | Writes the lockstep version into all surfaces |
| =.github/workflows/release.yml= | On =v*= tag: lockstep assert, Rust tests, =cargo publish=, GH Release |
| =.github/workflows/release-prepare.yml= | Dry-run / config validation (no publish) |
| =.github/workflows/potentials.yml= | Feature-gated C++ backends (xtb+tblite, metatomic/vesin) |

*Secrets (maintainer)*: repository secret =CARGO_REGISTRY_TOKEN= must be set for
=release.yml= to publish =rgpot-core= to crates.io (GH Release notes still need a
matching =CHANGELOG.md= section from towncrier).

** Changelog fragments

Each user-facing PR should add a fragment under =docs/newsfragments/=:

#+begin_src bash
uvx towncrier create --content "Short user-facing note." 42.added.md
# or interactive:
uvx towncrier create
#+end_src

Types (see =towncrier.toml=): =security=, =removed=, =deprecated=, =added=,
=dev=, =changed=, =fixed=, =misc=. Preview with =pixi r towncrier-draft=.

CI runs =towncrier check= on pull requests when fragments are required (see
=prek.toml= / release-prepare workflow). Pure =docs= / =ci= / =chore= commits
may omit fragments.

** Preparing a release (maintainer)

1. Ensure =main= is green (build matrix, =prek=, =docs_quality=).
2. Confirm fragments exist for everything since the last tag.
3. Dry-run (optional, also available as GHA =workflow_dispatch= on
   =release-prepare.yml=):

   #+begin_src bash
   cog bump --auto --dry-run
   # or: --patch / --minor / --major / --version 1.2.0
   #+end_src

4. Cut the release *locally* (needs push rights; does *not* publish to crates.io):

   #+begin_src bash
   cog bump --auto          # runs sync-versions.sh + towncrier build, commits, tags vX.Y.Z
   git push origin HEAD --follow-tags
   #+end_src

   Hooks (=cog.toml= =pre_bump_hooks=):

   - =scripts/release/sync-versions.sh {{version}}= — lockstep write
   - =uvx towncrier build --yes --version {{version}}= — update =CHANGELOG.md=, clear fragments

5. Tag push triggers =release.yml=:

   - Assert tag version equals meson + Cargo package versions
   - =cargo nextest= / doc tests for =rgpot-core=
   - =cargo publish= for =rgpot-core= (secret =CARGO_REGISTRY_TOKEN=)
   - GitHub Release body from the matching =CHANGELOG.md= section

Do *not* run =cargo publish= by hand unless CI is unavailable; the workflow is
the source of truth.

** Version policy

- *Lockstep*: C++ (=meson=), Rust crate (=rgpot-core=), docs towncrier stamp, and
  pixi workspace version share one =X.Y.Z=.
- *One global tag*: =vX.Y.Z= (not =rgpot-core-v…=).
- *Crate publish* ships =rgpot-core= only; C++ consumers track the git tag /
  source release, not crates.io.

** Emergency / hotfixes

#+begin_src bash
cog bump --patch
git push origin HEAD --follow-tags
#+end_src

For a named version (release candidate):

#+begin_src bash
cog bump --version 1.1.1
#+end_src

** Local checks before bump

#+begin_src bash
pixi r rust-test-all
pixi r prek
pixi r towncrier-draft
pixi r lychee-check   # optional link hygiene
bash scripts/release/sync-versions.sh 1.2.3   # must refuse garbage input
#+end_src
