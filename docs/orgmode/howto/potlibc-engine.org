* Use POTLIB surfaces through the potlibc engine

=libpotlibc_engine.so= is an optional engine plugin.
It keeps potlibc behind the generic engine C ABI: applications load one shared
library and pass one versioned create message.
There is no potlibc potential type or potlibc feature in =librgpot= or
=rgpot-core=.

** Install potlibc

Build and install potlibc first.
Its [[https://omnipotentrpc.github.io/potlibc/][surface catalog]] lists the
canonical surface ids and says which surfaces need an atom count.

#+attr_rgpot: syntax
#+begin_src bash
git clone https://github.com/OmniPotentRPC/potlibc.git
meson setup potlibc/build potlibc --prefix="$HOME/.local"
meson compile -C potlibc/build
meson install -C potlibc/build
#+end_src

Make the chosen prefix visible to =pkg-config= when it is not on the system
search path.

#+attr_rgpot: syntax
#+begin_src bash
export PKG_CONFIG_PATH="$HOME/.local/lib/pkgconfig:$PKG_CONFIG_PATH"
#+end_src

** Build the plugin

=with_potlibc= is a Meson =feature= option and defaults to =disabled=.
=enabled= requires the =potlibc= pkg-config dependency and builds
=libpotlibc_engine.so=.

#+attr_rgpot: syntax
#+begin_src bash
meson setup bbdir -Dwith_potlibc=enabled
meson compile -C bbdir libpotlibc_engine.so
meson test -C bbdir --print-errorlogs potlibc_engine
#+end_src

The plugin is separate from =librgpot=.
No potlibc symbols or headers enter the core library.

** Create a surface

=include/rgpot/potlibc_engine.h= declares =RgpotPotlibcConfigV1=.
Set its magic and version, copy one canonical catalog id into
=surface_id=, and set =atom_count= to zero for a fixed-size surface or to the
exact count for a variable-size surface.
The plugin calls =potlibc_create= in the first case and =potlibc_create_sized=
in the second; it does not retry with another constructor.

#+attr_rgpot: compile flags=-ICppCore -Iinclude
#+begin_src c
#include <string.h>

#include "rgpot/engine_c_abi.h"
#include "rgpot/potlibc_engine.h"

int main(void) {
RgpotPotlibcConfigV1 cfg = {
    .magic = RGPOT_POTLIBC_CONFIG_MAGIC,
    .version = RGPOT_POTLIBC_CONFIG_VERSION,
    .atom_count = 0,
};
strcpy(cfg.surface_id, "brh2leps");

char error[512];
RgpotEnginePot *pot =
    rgpot_engine_create(&cfg, sizeof cfg, error, sizeof error);
rgpot_engine_destroy(pot);
return pot == NULL;
}
#+end_src

The engine ABI takes Angstrom and returns eV and eV/Angstrom.
The plugin performs the conversion to potlibc's Bohr and Hartree units.
When potlibc metadata gives atomic number 0 for an atom, that position is
unspecified and the plugin accepts the caller's species.
A nonzero catalog atomic number must match exactly.

** Load it from Rust

Enable the generic loader, not a potlibc-specific feature.

#+attr_rgpot: syntax
#+begin_src toml
[dependencies]
rgpot-core = { version = "3.7.0", features = ["engine"] }
#+end_src

Serialize the bytes of =RgpotPotlibcConfigV1= in the host language and pass them
to =EnginePotential::load= with the path to =libpotlibc_engine.so=.
=EnginePotential::force= evaluates energy and forces.
=EnginePotential::hvp= uses =rgpot_engine_hvp= only when the surface advertises
an analytic product, and =into_potential= exposes that same handle to in-process
and RPC callers.

The complete symbol contracts and units are in the
[[file:../reference/engine_abi.org][engine ABI reference]].
