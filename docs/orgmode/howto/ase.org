* ASE calculators

=rgpot.ase= is an optional extra (=pip install 'rgpot[ase]'=, ASE 3.23 or
newer).
=import rgpot= does not import ASE.
=RgpotCalculator= runs a potential in this process.
=RgpotRpcCalculator= sends each structure to a =potserv= server over Cap'n
Proto.
Both are ordinary =ase.calculators.calculator.Calculator= subclasses, so
optimizers, filters, NEB, dynamics and trajectory writers use them the way
they use a built-in calculator.

ASE itself is described by Hjorth Larsen et al., J. Phys.: Condens.
Matter 29, 273002 (2017), doi:10.1088/1361-648X/aa680e.

** Example

This relaxes the atoms and the cell of a rattled silicon crystal with the
Stillinger-Weber potential.

#+begin_src python
from ase.build import bulk
from ase.filters import FrechetCellFilter
from ase.optimize import BFGS
from rgpot.ase import RgpotCalculator

atoms = bulk("Si", "diamond", a=5.6, cubic=True)
atoms.rattle(stdev=0.05, seed=1)
atoms.calc = RgpotCalculator("stillinger_weber_si")

print(atoms.get_potential_energy())   # eV
print(atoms.get_forces()[0])          # eV/Angstrom
print(atoms.get_stress())             # eV/Angstrom^3, Voigt order

BFGS(FrechetCellFilter(atoms), logfile=None).run(fmax=1e-4)
print(atoms.cell.lengths())           # [5.431 5.431 5.431]
print(atoms.get_potential_energy() / len(atoms))  # -4.334 eV per atom
#+end_src

A potential with parameters takes them as keyword arguments, and =set=
changes them later.
The slab is made periodic along z as well, because the potentials take either
all-periodic or all-free boundaries; the vacuum keeps the slab's images
apart.

#+begin_src python
from ase.build import fcc100, add_adsorbate
from rgpot.ase import RgpotCalculator

slab = fcc100("Ar", size=(3, 3, 3), a=1.5496, vacuum=5.0)
add_adsorbate(slab, "Ar", 1.0, "hollow")
slab.pbc = True
slab.calc = RgpotCalculator("lj", u0=1.0, psi=1.0, cutoff=2.5)
print(slab.get_potential_energy())

print(slab.calc.set(cutoff=3.0))      # {'cutoff': 3.0}
print(slab.get_potential_energy())    # recomputed with the new cutoff
#+end_src

** Potentials and properties

The first argument is a kind string from the table, or a potential object
from =rgpot= (=rgpot.LJPot(...)=, =rgpot.IPIPot(...)=, and so on).
Every potential gives =energy=, =free_energy= and =forces=.
The stress column says whether =stress= is in =implemented_properties=.
A potential with "free" boundaries accepts only =pbc=False=.

The Fortran kernels (=sw= to =water_h=), =d3=, =d4= and =expr= exist only in a
build that compiled them in.
=lammps= needs its engine plugin, either on the library path or as
=engine_path=.
=IPIPot= is an i-PI socket server: an i-PI driver must connect to it, and the
stress comes from the virial the driver sends back.

No potential computes per-atom energies, so =energies= is never in
=implemented_properties=.
Asking for a property that is not in the list raises
=PropertyNotImplementedError=, as a built-in calculator does.
=get_hessian= raises it too, because no potential has an analytic Hessian.
=free_energy= equals =energy=: these potentials have no electronic entropy.

** Units and conventions

Energy is in eV, forces in eV/Angstrom and stress in eV/Angstrom^3.
Stress is in ASE's Voigt order (xx, yy, zz, yz, xz, xy) with ASE's sign: it is
\((1/V)\,\partial E/\partial \varepsilon\), so a compressed crystal has
negative stress and =atoms.get_stress()= agrees with
=ase.calculators.fd.calculate_numerical_stress=.

** Boundaries

A structure with every =pbc= flag true is periodic in its cell.
The potentials count each neighbour at its nearest periodic image, which is
right only when every cell height is at least twice the cutoff.
A thinner cell, such as a one-atom fcc cell, is evaluated as a supercell that
is thick enough, and the energy, forces and stress of the original cell are
taken from it, so the results match ASE's own calculators for any cell.
=water_h= has no cutoff and is not tiled.
For an =IPIPot= or a potential object without =config()=, the calculator does
not know the cutoff, so the cell must be thick enough already.

A structure with every flag false is a cluster.
For a cluster, the potential sees a cube whose side is at least 100 Angstrom
and at least the cluster size plus twice the cutoff, so no periodic image is
within the cutoff, and energy and forces do not depend on the cell you set.
Stress does: it is the cluster virial divided by your cell's volume, which is
what finite differences of that cell measure.
A cluster with no three-dimensional cell has no stress, and =get_stress=
raises =PropertyNotImplementedError=.
Mixed flags such as =pbc=[True, True, False]= raise =ValueError=.
A free-boundary potential (=lj_cluster=, =d3=, =d4=) raises =ValueError= for
periodic atoms instead of returning the energy of the isolated structure.

** Parameters, caching and copies

The potential's parameters live in =calc.parameters= next to ASE's own, and
=calc.default_parameters= holds their defaults.
An unknown parameter raises =ValueError= and names it.
=set= returns the keys whose value changed, rebuilds the potential and
clears the results when any of them did.
=calc.todict()= lists the parameters that differ from the defaults.

Results are cached in the usual ASE way.
Asking again for a property of unchanged atoms returns the stored value
without evaluating the potential.
A change of positions, atomic numbers, cell or =pbc= evaluates it again.
=get_property(name, atoms, allow_calculation=False)= returns =None= instead
of computing a missing result.

=copy.deepcopy= and =pickle= work for a calculator built from a kind string or
from a potential that reports =config()=: the copy builds its own potential
from the parameters.
A calculator over an object with no =config()=, such as =IPIPot=, raises
=TypeError= on copy, because the object holds an engine or socket that cannot
be copied.

** Batches

=calculate_many= evaluates a list of =Atoms= in one batch.
The default properties are energy and forces.
Pass =attach=True= to store a =SinglePointCalculator= on each structure.
The inputs are not modified.

** RPC calculator

=RgpotRpcCalculator= is the Cap'n Proto calculator.
Its =implemented_properties= is =energy=, =free_energy= and =forces=.
Periodic atoms go to the server in their cell; a cluster goes in the same
padded cube as above.
The calculator cannot ask the server for its cutoff.
Pass =cutoff= (Angstrom) and a cell thinner than twice it is sent as a
supercell, as above.
=RgpotRpcCalculator.spawn= sets it for =LJ=, =Morse=, =CuH2= and =EAMAl=.
One connection belongs to one calculator, so it cannot be copied or pickled.
A second thread that enters =calculate= while the first still holds the
connection gets =RuntimeError=.
The old import =ase_calculator.RgpotCalculator= warns and re-exports this class.

** Annealing helper

=AnnealRunner= calls =anneal.global_optimize= and writes the best geometry back
onto the atoms.
It is not an =ase.optimize.Optimizer=.
=AnnealOptimizer= is the old name and warns on construction.
