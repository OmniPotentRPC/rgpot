* ORCA single points

=ORCAPot= gives ORCA the normal rgpot =Potential= interface.
Each force call runs one ORCA energy and gradient and returns them in eV and
eV/Angstrom.
The class is in =CppCore/rgpot/ORCAPot/= and reports =PotType::ORCA=.
It starts the =orca= executable as a child process, so rgpot links no ORCA
library and carries no ORCA code.
You install ORCA yourself and accept its license.

ORCA is described in Neese, WIREs Computational Molecular Science 2, 73-78
(2012),
doi:10.1002/wcms.81. The program paper is Neese, Wennmohs, Becker and Riplinger, J. Chem. Phys. 152, 224108 (2020), doi:10.1063/5.0004608.
The version 5 update is Neese, WIREs Computational Molecular Science 12, e1606
(2022),
doi:10.1002/wcms.1606. The version 6 update is Neese, WIREs Computational Molecular Science 15, e70019 (2025), doi:10.1002/wcms.70019.
[[file:../reference/cpp_backends.org][The backend reference]] lists the class
members.

** Build

=ORCAPot= is off by default.
Meson turns it on with =-Dwith_orca=true= and CMake with =-DRGPOT_WITH_ORCA=ON=.
It needs =fork= and =exec=, so enabling it on Windows is a configure error.
The option does not look for ORCA.
The executable is found when an =ORCAPot= is constructed, so a build made on a
machine without ORCA runs wherever ORCA is installed.

#+attr_rgpot: syntax configures a build with the ORCA frontend
#+begin_src bash
meson setup bbdir -Dwith_orca=true -Dwith_tests=true
meson test -C bbdir ORCAPotTest
#+end_src

** Configuration

=ORCAConfig= holds every choice.
There is no default method or basis, and no ORCA path is built in.

| Field          | Meaning                                                           |
|----------------+-------------------------------------------------------------------|
| =executable=   | A path to =orca=, or a bare name; empty looks up =orca= on =PATH= |
| =method=       | The ORCA method keyword; required                                 |
| =basis=        | The basis set keyword; empty for a composite method               |
| =keywords=     | Further simple-input keywords, such as =TightSCF D4=              |
| =charge=       | Total charge, default 0                                           |
| =multiplicity= | Spin multiplicity 2S + 1, default 1                               |
| =nprocs=       | Processes for =%pal=, default 1                                   |
| =maxcore_mb=   | =%maxcore=, MB per process, default 1024 (ORCA's own default)     |
| =restart=      | Reuse the previous orbitals, default true                         |
| =scratch_dir=  | Where the working directory is made; empty uses the temp directory |
| =keep_files=   | Keep the working directory after the instance is destroyed       |
| =timeout_s=    | Seconds for one orca run; default 3600, and 0 waits with no limit |

The executable is the =executable= field when it is set, and otherwise the first
=orca= in the directories of =PATH=.
A bare name in =executable= is looked up the same way, and symlinks to
executable regular files are accepted.
ORCA starts its own MPI processes when =nprocs= is above 1, and it must then be
started by its full path, so =ORCAPot= always runs the absolute path.
=ORCAPot::executablePath()= reports it.

** Time limit

The =orca= process is the leader of a new process group.
=timeout_s= is how many seconds that process may run.
The default is =ORCAConfig::kDefaultTimeout=, 3600 seconds, one hour.
Zero waits until the process ends, for a single point that needs longer.
When the limit passes, the group is sent SIGTERM.
If any process in the group is still alive two seconds later, the group is sent
SIGKILL even if the leader has already exited.
The child is reaped and the group is waited on, and the call throws =ORCAError=.
Children that stay in the group, including ORCA's MPI ranks, are stopped with
it.
A =timeout_s= that is negative or not finite throws =std::invalid_argument= from
the constructor.
=paramsKey()= leaves the limit out, because it does not change the energy.

#+attr_rgpot: fragment needs -Dwith_orca=true and ORCA installed
#+begin_src cpp
#include "rgpot/ORCAPot/ORCAPot.hpp"

#include <array>
#include <vector>

rgpot::ORCAConfig cfg;
cfg.method = "PBE";
cfg.basis = "def2-SVP";
cfg.keywords = "TightSCF";
cfg.nprocs = 4;
cfg.maxcore_mb = 2000;

rgpot::ORCAPot pot(cfg);
std::vector<int> z = {8, 1, 1};
std::vector<double> xyz = {0.0, 0.0, 0.1173, 0.0, 0.7572, -0.4692,
                           0.0, -0.7572, -0.4692};
rgpot::ForceOut out{};
std::vector<double> forces(xyz.size());
out.F = forces.data();
pot.forceImpl(rgpot::ForceInput{z.size(), xyz.data(), z.data(), nullptr}, &out);
#+end_src

** Units

rgpot positions are Angstrom, which is also the unit of an ORCA =* xyz= block,
so the coordinates are written as they are.
The =.engrad= file holds the energy in Hartree and the gradient in
Hartree/bohr. =ORCAPot= multiplies the energy by =units::HARTREE_TO_EV= and the gradient by =units::NEG_GRAD_TO_FORCE=, both from =CppCore/rgpot/units.hpp=. The forces are the negative gradient in eV/Angstrom.
The variance is 0 and no stress is written.

** Restarting from the previous wavefunction

With =restart= on, which is the default, the converged orbitals of one call
start the next.
After a call, ORCA's =rgpot_orca.gbw= is copied to =rgpot_orca_guess.gbw=.
The next input then carries =%moinp "rgpot_orca_guess.gbw"= and =MORead= on its
=!= line.
The copy has a name of its own because ORCA overwrites its own =.gbw=, and an
input that names the file it is about to write would lose the guess.

The call starts from ORCA's own guess instead when

- no =.gbw= exists, because ORCA wrote none or the copy was deleted,
- the atomic numbers differ from those of the call that made the orbitals,
- the previous call failed,
- =reset()= was called, or
- =restart= is false.

=reusedWavefunction()= tells whether the last successful call read orbitals.
A restart helps along a path of nearby geometries.
After a large jump, call =reset()= so the guess does not pull an SCF into the
wrong state.

** Working directory

Every instance makes a directory of its own with =mkdtemp= under =scratch_dir=,
or under the system temporary directory when that is empty.
It holds =rgpot_orca.inp=, =rgpot_orca.out=,
=rgpot_orca.err=, =rgpot_orca.engrad=, the =.gbw= files and whatever else ORCA
writes.
Two instances never share a directory, so two instances may run at once, each
from its own thread.
The directory is removed when the instance is destroyed, unless =keep_files= is
set.
=runDirectory()= reports it.
Before each run the old =.engrad= and =.gbw= are deleted, so a result of an
earlier call cannot pass for this one.
Any removal failure other than a missing file throws =ORCAError=.
Extra file descriptors above 2 are closed before =exec=, and inputs and
=.engrad= files are formatted and parsed independently of the process locale.

** Errors

An error in the run throws =rgpot::ORCAError=, a =std::runtime_error=.
That covers a stale =.engrad= or =.gbw= that cannot be removed, a missing
executable, a process that cannot start, a run past =timeout_s=, a process
killed by a signal, a non-zero exit status, a missing or malformed =.engrad=, an
=.engrad= for other atoms, and an energy or gradient that is not finite.
The message names the input file and ends with the last 2048 bytes of the
standard error and of the output file, where ORCA reports an SCF failure or an
input mistake.
A failed call also drops the stored orbitals.

Input the caller got wrong throws
=std::invalid_argument=: an empty method, a line break in a keyword field, a counter below 1, a =timeout_s=
that is negative or not finite, an atomic number outside 1 to 118, and a charge
and multiplicity that the electron count cannot hold.

** Limits

- ORCA has no periodic boundary conditions.
  =caps().periodic= is false, and a force call with a box that has any non-zero
  entry throws =std::invalid_argument=.
  Pass no box, or an all-zero box, as for the other non-periodic potentials.
- No stress is written.
- The potential is per instance: =caps().reentrancy= is
  =Reentrancy::PerInstance=.
  Give each thread its own =ORCAPot=.
- Each call starts a process, so a call costs the ORCA start-up time on top of
  the SCF.
  The class suits a few hundred to a few thousand single points.
- There is no =potserv= backend, engine plugin or Python class for it yet.

** Tests

CI has no ORCA.
=ORCAPotTest= writes a small fake =orca= shell script into a temporary
directory.
The script checks the keyword line, =%maxcore=, the coordinates, closed extra
file descriptors and the =MORead= and =%moinp= lines of the input it is given,
keeps a copy of each input, writes an =.engrad= of known numbers and a =.gbw=
that names the call, and can fail, sleep past =timeout_s= with a child that
ignores SIGTERM (both when the leader stays alive and when the leader exits on
SIGTERM), write nothing, write NaN, write a short file or kill itself.
The test then checks the unit conversion, the restart, the fall-back to a fresh
guess, the error paths (including a stale =.engrad= that cannot be removed),
symlink executables, comma-decimal locales and the rejection of a periodic box.
One test case runs a real ORCA and is skipped, with the message "orca is not on
PATH", when =ORCAPot::probeAvailable()= is false.
